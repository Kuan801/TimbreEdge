# TimbreClone — Teensy 4.1 即時樂器音色複製

聽一個單音 → 萃取音色指紋 → 重建這個樂器 → 用任何音高把它彈回來。

輸入可以是 SD 卡上的 WAV，也可以是 Audio Shield 麥克風現場錄的 2 秒。

---

## 硬體

| 項目 | 說明 |
|---|---|
| Teensy 4.1 | 600 MHz Cortex-M7、1 MB RAM |
| Teensy Audio Shield (Rev D) | SGTL5000 codec，44.1 kHz stereo I²S |
| microSD 32 GB | FAT32 或 exFAT。**建議插 Teensy 4.1 板子背面的內建插槽**（SDIO 比 Audio Shield 的 SPI 快很多），程式會自動偵測，找不到才退回 Shield 的插槽 |
| 麥克風 | Audio Shield 的 MIC 焊盤（駐極體麥克風 + 板上偏壓），或改用 LINE IN |
| OLED 128×64 | I2C：**SDA = 18，SCL = 19**，VCC 接 3.3V。與 SGTL5000 共用 I2C 匯流排，位址不衝突（OLED 0x3C／codec 0x0A）。需要 **U8g2** 函式庫（Library Manager 搜尋 U8g2 安裝）。沒接面板就把 `config.h` 的 `TC_USE_OLED` 改成 0 |
| 按鈕（可選） | D2 = 錄音並分析，D3 = 演奏 / 停止。接地觸發，程式已開 `INPUT_PULLUP`，不接也能用序列埠操作 |
| 耳機 / 喇叭 | 接 Audio Shield 的 HEADPHONE 或 LINE OUT |

需要的 Arduino 函式庫：`Audio`、`SD`、`SPI`、`Wire` 隨 Teensyduino 附帶；
**`U8g2` 要自己裝**（Library Manager 搜尋 U8g2）。不接 OLED 的話把
`config.h` 的 `TC_USE_OLED` 改 0，就完全不需要 U8g2。
**Tools → USB Type 要選 "Serial"**，序列埠 115200。

## 30 秒上手

1. 把 `TimbreClone/` 整個資料夾丟進 Arduino IDE 開啟 `TimbreClone.ino`，選 Teensy 4.1，燒錄。
2. 開序列埠監控視窗（115200）。
3. 輸入 `r`，對著麥克風拉 / 吹 / 彈**一個持續的單音**約 2 秒。
4. 錄完會自動分析，OLED 上會出現**這次錄音行不行的判定**（峰值、訊噪比、
   起音次數、衰減），看完之後才自動演奏，讓你聽到合成結果。

想用現成音檔的話，把 16-bit WAV 複製到 SD 根目錄，然後輸入 `a MYNOTE.WAV`。

### 序列埠指令

| 指令 | 作用 |
|---|---|
| `r` | 麥克風錄一段 → `REC.WAV`，錄完自動分析並演奏 |
| `s` | **連續採樣模式**：偵測到聲音就自動錄+命名+入庫，一個人就能採完整個音域 |
| `g [0-63]` | 麥克風增益 |
| `o` | **輸入電平監看**：即時印出 RMS/峰值，麥克風沒反應時先用這個 |
| `v` | 顯示音色庫的音域覆蓋 |
| `a` / `a 檔名.WAV` | 分析 SD 上的 WAV。不帶檔名 = 分析 `REC.WAV` |
| `d` | 列出 SD 根目錄。找不到檔案時先用這個；SD 沒掛起來時會順便重試掛載 |
| `n [目標]` | 分析並**加入訓練集**。目標可以是空白（`REC.WAV`）、單一檔名、以空白分隔的多個檔名、`*`（根目錄全部 WAV）、或 `SAMPLES/`（該資料夾全部 WAV） |
| `t` / `t 8000` | **在 Teensy 上直接訓練 MLP**，完成後自動存 `MODEL.BIN`、套用、並演奏＋錄成 `PLAY.WAV` |
| `z` | 清空訓練集 |
| `w` | 演奏並同步錄成 `PLAY.WAV` |
| `c` | 切換是否同時匯出 `FRAMES.CSV`（拿去電腦訓練 MLP 用） |
| `p` / `x` | 演奏半音階（音域跟著音色庫走）/ 停止 |
| `j` / `j n` | **演奏卡農**（三聲部，拿來聽的）並錄成 `CANON.WAV` / 只演奏不錄檔 |
| `l` | 重新載入 `PROFILE.BIN`（分析完會自動存，不需要手動存） |
| `m` | 重新載入 `MODEL.BIN` |
| `k` | **A/B：MLP 混合權重在 0 與 `TC_MLP_BLEND_AB`（0.35）之間切換**，可以直接聽差別 |
| `i` | 切換麥克風 / 線性輸入 |
| `u` | **USB MTP 磁碟機開關**（把 SD 掛給電腦看）。只在 USB Type 選了 `Serial + MTP Disk` 時才存在 |
| `+` `-` | 主音量 |
| `?` | 說明 |

## 它是怎麼運作的

```
              [SD 上的 WAV]  或  [麥克風 5 秒]
                        │
                        ▼
   ┌─────────────────── 分析（離線，約 1~3 秒）───────────────────┐
   │  RMS 包絡  →  onset / peak / offset  →  ADSR + 持續段衰減率   │
   │  YIN       →  基頻 f0（取 9 個候選的中位數）                  │
   │  2048-pt FFT × 每 512 取樣  →  32 個諧波的振幅軌跡            │
   │  外差解調（2.9ms 解析度） →  逐諧波起音延遲 + shimmer 深度     │
   │  持續段平均頻譜  →  log 頻譜包絡（共振峰）64 點               │
   │  總能量 − 諧波能量  →  噪聲比（氣聲 / 弓噪）                   │
   │  諧波峰位偏移  →  非諧性係數 B（鋼琴 / 吉他的弦張力效應）      │
   └───────────────────────────┬───────────────────────────────┘
                               ▼
                    InstrumentProfile（音色指紋，存 PROFILE.BIN）
                               │
       ┌───────────────────────┴───────────────────────┐
       ▼                                               ▼
 [有 MODEL.BIN]                                  [沒有 MODEL.BIN]
  4-32-32-33 MLP                                 32 個關鍵影格內插
  （對數時間軸）                                 （對數時間軸）
  每 2.9 ms 推論一次                              （音色一樣可用，只是
                                                   少了響度適應）
       └───────────────────────┬───────────────────────┘
                               ▼
                  頻譜包絡校正（移調時保住共振峰）
                               ▼
   ┌──────────────── 合成（即時，audio ISR）────────────────┐
   │  8 複音 × 最多 64 根諧波（依音高自動配置）                │
   │  + 逐諧波非同步起音 + 逐諧波 shimmer + 起音噪聲爆點       │
   │  振幅每個 block 更新、block 內線性斜坡（不會有階梯感）   │
   │  接近 Nyquist 的諧波 cosine 淡出（抗混疊）              │
   └──────────────────────────┬────────────────────────────┘
                              ▼
                   Freeverb → SGTL5000 → 耳機
```

### 真實度：四個量測出來的問題與對策

早期版本聽起來很「電子」。用量測找出四個具體原因，逐一修掉：

| 問題 | 量到的證據 | 對策 |
|---|---|---|
| **低音悶** | 諧波固定 16 根，D2(73Hz) 最高只到 **1184 Hz**，以上全靜音，低音幾乎只剩基頻 | 依音高自動配置，上限 **64 根**。D2 現在到 4.7 kHz，低音段實測 99% 能量截止從 1175 → **6929 Hz** |
| **起音全同步** | 所有諧波在同一個 125 ms 到達 50%，真實樂器是分散的 | 外差解調量測逐諧波延遲，合成端逐諧波閘控。實測從「全部 125 ms」變成 **6~55 ms 分散** |
| **起音沒被建模** | 32 個關鍵影格平均攤在 5 秒上 = 每格 153 ms，整個起音塞不滿一格 | 改用**對數時間軸**，前 200 ms 拿到 1/3 格數、前 500 ms 拿到一半 |
| **長音太死** | 逐諧波微觀起伏：來源 8.3%，合成只有 **0.7~3.4%** | 每根諧波獨立的慢速擺動（2.5~7.5 Hz 打散）。實測 **7.8~8.2%**，與來源吻合 |

順帶修掉兩個量測本身的缺陷：諧波能量原本用 `峰值²×3` 近似，常常高估到把噪聲比壓成 0，
噪聲層等於失效——改成實際加總峰值周邊的 bin；起音判定原本看「第一次越過門檻」，
但起音瞬間的寬頻爆點會讓所有諧波同時被激發，導致非同步性完全量不出來——
改成要求連續 3 格。

代價是 CPU 從約 12% 上升到約 40%（同機渲染時間 3.1 倍）。另外加了
**全域 partial 預算**（`TC_PARTIAL_BUDGET`）：尾音疊起來最壞會到 8 複音 × 64 根 = 512 根，
超過預算就等比例縮減，寧可略微變悶也不爆音。

`demo/canon_v1_before.wav` 與 `demo/canon_v2_after.wav` 是同一份素材、同一份樂譜的 A/B。

### 「機器學習」到底做了什麼

那顆 MLP 很小，是刻意的：**輸入 4 → 32 → 32 → 33**，2305 個參數，9 KB。

```
輸入： [ log2(f0/261.63)/1.0 , 響度 , 對數時間軸位置 , 是否已放開 ]
輸出： 32 個諧波權重（softmax） + 1 個噪聲增益（sigmoid）
       第 33~64 根諧波改由量測到的頻譜包絡外推
```

它每 2.9 ms 為每個發聲的音跑一次推論。單次約 2.2 k MAC，8 複音下約
6 M MAC/s — 在 600 MHz 帶 FPU 的 M7 上不到 3% CPU。

**為什麼可以這麼小？** 因為最難的那件事（換音高時共振峰會跑掉）已經用
DSP 解掉了：頻譜包絡校正讓每個諧波去查它「新的絕對頻率」在包絡上的增益，
再除掉參考音高下的增益。共振峰因此留在原位，音色不會變成花栗鼠。
MLP 只需要負責「響度 / 時間 / 音區」造成的音色變化 —— 這部分低維又平滑，
一個小網路就學得很好（實測諧波分佈平均誤差 0.0004）。

這其實就是 DDSP（Differentiable Digital Signal Processing）的核心想法：
用網路預測物理合成器的參數，而不是硬要網路直接吐波形。Teensy 跑不動
神經聲碼器，但跑得動這個。

**沒有 MODEL.BIN 也能用。** 會自動退回 32 個關鍵影格的線性內插，一樣有
隨時間變化的音色，只是少了對響度的非線性適應。按 `k` 可以直接 A/B。

`k` 切換的是**混合權重**（0 ↔ 0.35），不是「有沒有載入權重」。舊版切的是後者，
但預設 `TC_MLP_BLEND` 就是 0，兩邊聽起來完全一樣 —— 那是一個沒有作用的開關。
順帶一提，`blend` 為 0 時整段 MLP 推論會被跳過（守衛條件是 `mlpActive()`），
省下每個聲部每個 block 的 2208 MAC 與 32 對 `logf`/`expf`。

## 訓練 MLP：機上訓練（不用電腦）

Teensy 4.1 跑得動整個訓練，不必把檔案送回電腦。

**一次載入多個素材**——把 WAV 全部丟進 SD 卡，然後：

```
n *              根目錄所有 WAV 一次載入
n SAMPLES/       某個資料夾的全部 WAV
n A3.WAV E4.WAV  指定幾個
n                只加 REC.WAV（配合 r 錄音使用）
t                訓練，完成後自動存 MODEL.BIN、套用、並演奏＋錄成 PLAY.WAV
```

掃描會依檔名排序後載入（訓練結果才可重現），自動跳過 `PLAY.WAV`（那是輸出，
不是素材）與非 `.WAV` 檔。單一檔案分析失敗只會跳過該檔，不會中斷整批。

序列埠會即時印出收斂狀況：

```
[TRAIN] 訓練集：1274 筆樣本，涵蓋 3 個音高，佔用 104 KB
[TRAIN] 開始：1274 筆樣本，batch 128，6000 epochs，lr 0.0030
        epoch     0   CE 2.9637   平均諧波誤差 0.07019
        epoch  3000   CE 2.0361   平均諧波誤差 0.00044   (11 s)
        epoch  6000   CE 2.0351   平均諧波誤差 0.00023   (22 s)
[TRAIN] 完成。最終 CE 2.0351，平均諧波誤差 0.00023
        品質：很好
```

**成本**（每筆樣本前向 2208 + 反向 4300 ≈ 6500 MAC，6000 epoch × batch 128
= 768k 次樣本傳遞 ≈ 5.0 G MAC）：

| 項目 | 數字 |
|---|---|
| 訓練時間 | 估 **20～40 秒**（依 cycle/MAC 落在 2～4 之間；實際秒數會印出來） |
| 訓練資料 | 每筆 84 bytes（平方根壓伸 int16），2560 筆上限 = 210 KB |
| Adam 狀態 + 梯度 | 27 KB |
| 加上分析器與權重的 OCRAM 總量 | 約 330 KB / 512 KB |

`t` 可以帶 epoch 數：`t 12000` 練久一點，`t 2000` 快速試。

訓練期間 audio ISR 照常運作（它是中斷，優先權比 `loop()` 高），不會爆音，
只是那幾十秒不能演奏。**訓練集存在 RAM，關機就沒了**，但 `MODEL.BIN` 已經
寫進 SD 卡，重開機會自動載入。

> 機上訓練與 Python 版用的是同一套數學（同樣的特徵、損失、Adam 超參數），
> 連 `tanh` 都刻意共用同一份 Padé 近似——避免「訓練用精確 tanh、推論用近似值」
> 的 train/inference mismatch。實測兩邊都收斂到平均諧波誤差 0.0002 左右。

## 訓練 MLP：電腦端（想調超參數時用）

只需要 numpy，反向傳播是手刻的，不用裝 PyTorch。

```bash
# 方法一：直接餵單音 WAV。同一把樂器、不同音高越多越好（3~8 個就很夠）
python3 tools/train_ddsp.py violin_a3.wav violin_e4.wav violin_c5.wav -o MODEL.BIN

# 方法二：吃 Teensy 上按 'c' 匯出的逐格分析檔
python3 tools/train_ddsp.py --csv FRAMES.CSV -o MODEL.BIN
```

把產生的 `MODEL.BIN`（9224 bytes）複製到 SD 卡根目錄，Teensy 開機或按 `m`
就會載入。

> 只錄一個音高也可以訓練，MLP 會學到「時間 / 響度」的影響；跨音高的部分
> 交給頻譜包絡校正。但多錄幾個音高，效果明顯更好。

## 先在電腦上聽（強烈建議）

`tools/sim/` 是一個桌機模擬器，用**跟 Teensy 上完全同一份**的
analyzer / timbre_model / additive_synth / score / player 程式碼，
把半音階算成 WAV 檔。調參數時比反覆插拔 SD 卡快太多。

```bash
cd tools/sim
make
./sim ../../你的單音.wav MODEL.BIN out.wav   # MODEL.BIN 可留空字串 ""

# 也可以跑「跟 Teensy 上完全同一份」的機上訓練程式碼，先看會收斂到哪
./sim train MODEL.BIN a3.wav e4.wav c5.wav
```

`demo/` 底下是改版前後的 A/B：`canon_v1_before.wav` 與 `canon_v2_after.wav`，
同一份素材、同一份樂譜，只差在上面那四項真實度修正。

## 音色庫：每個音用最接近的取樣點

只留一組 profile 的話，整個音域都得靠移調硬撐。真實鋼琴每個音區差很多
（低音多弦、高音單弦、擊弦點比例也不同），移調兩個八度出來一定不像。

`n *` 批次載入時，每分析一個檔就存進音色庫（最多 16 組，約 73 KB），
演奏時每個音符各自挑**音高最接近的那組**，移調距離縮到半音以內。
音色庫存在 SD 的 `BANK.BIN`，開機自動載入。

用 Iowa MIS 鋼琴 C4~B4 共 12 個素材實測（見下節的評測工具）：

| 指標 | 單一 profile | 12 組音色庫 |
|---|---|---|
| 包絡相關性 r | 0.973 | **0.992** |
| 諧波 LSD（中段） | 5.5 dB | **1.5 dB** |
| 頻譜圖 MAE | 3.4 dB | **1.4 dB** |
| 質心相關性 r | 0.174 | **0.895** |

質心相關性從 0.17 跳到 0.90 是最說明問題的一項——單一 profile 移調之後，
「亮度隨時間怎麼變」幾乎是亂的。

## 客觀評測與 Word 報告

一句話：**用 SD 卡上的乾淨音源建音色 → 讓機器演奏半音階並錄下來 →
逐音跟原始素材比對 → 產生 Word 報告。**

### 完整流程

```bash
# --- 1) 在 Teensy 上（素材已經在 SD 卡根目錄）------------------------------
#   n *        掃描根目錄所有 WAV，逐一分析建立音色庫
#   v          確認音色庫涵蓋哪些音（後面 --start 要用）
#   w          演奏半音階並同步錄成 PLAY.WAV
#   把 SD 卡插到電腦上，複製 PLAY.WAV 出來

# --- 2) 在電腦上 -----------------------------------------------------------
cd tools
python3 evaluate.py PLAY.WAV /path/to/素材資料夾/ \
        --start 60 --count 24 \
        --json report.json --plot report.png

python3 report_docx.py report.json --plot report.png \
        --out 音色比對報告.docx \
        --source "Iowa MIS 鋼琴 mf，C4~B4 共 12 音" \
        --method "Teensy 4.1 實機，按 w 錄成 PLAY.WAV"
```

**`--start` 一定要給對。** 半音階的音域是「音色庫涵蓋的範圍再往上一個八度」，
不是寫死的 C3。素材是 C4~B4 的話，合成檔就是 C4~B5 → `--start 60 --count 24`。
給錯的話配對會整個錯位，而且**不會報錯**，只會得到一堆很難看的數字。
按 `v`（Bank coverage）或看演奏開始時序列埠印的 `[SCORE] C4-B5 scale` 就知道。

### 不想動硬體的話

`tools/sim` 用**跟韌體完全同一份** analyzer / timbre_model / additive_synth /
player 程式碼，在桌機上把同一首半音階算出來：

```bash
cd tools/sim && make sim
cd /你的素材目錄 && /path/to/sim scale.wav "" *.wav
```

音域規則也跟韌體一致（音色庫範圍 + 一個八度），所以 `--start` 用一樣的值。
差別只在沒有經過 SD、DAC、類比輸出 —— 想證明「機器真的做得到」就用實機，
想快速反覆調參數就用模擬器。

### 報告裡有什麼

| 節 | 內容 |
|---|---|
| 一 | 量測條件（素材、合成方式、檔案、音數、對齊方式） |
| 二 | 逐音對照大表，9 個指標 × 每個音，綠／黃／紅底標示 |
| 三 | 指標與判讀標準，附本次平均 |
| 四 | 比較圖（頻譜圖、包絡、逐音指標曲線） |
| 五 | 逐音明細，列出每個音哪幾項超標 |

**報告不下結論**，只放量到的數字與判讀標準 —— 結論該由看報告的人依標準自己判斷。

判讀標準定義在 `evaluate.py` 的 `CRITERIA`，`report_docx.py` 直接 import 它，
不重抄一份。抄兩份的下場是改了門檻只改一邊，而報告上的顏色與結論照舊 ——
那種錯不會有任何跡象。

同理，`report_docx.py` 吃的是 `--json` 而不是去解析終端機印出來的表格：
那張表是給人看的，欄寬隨時會為了好讀而調整，拿它當資料介面會在某次改對齊之後
靜靜地錯位。

| 指標 | 量什麼 | 很好 |
|---|---|---|
| 包絡相關性 r | 音量隨時間的形狀（對數域） | > 0.95 |
| 衰減時間誤差 | 掉到 −20 dB 要多久 | < 200 cent |

## 頻譜包絡曾經還留著梳狀結構

用小號測「只用 C4~B4 訓練、外推到 E3~B5」時發現的。症狀很特別：**誤差對移調
距離是非單調的**。F5（+6 半音）的基頻只剩 1.0%（真值 30%），但 B5（+12 半音）
反而只錯到 45.5 / 69.8。

原因是 `specEnv` 用「±12% 視窗取峰值」，而那個視窗遠比諧波間距窄。B4 的諧波
間隔 494.6 Hz，查 698 Hz（h1 與 h2 正中間）時視窗只涵蓋 614~782 Hz，一根諧波
都沒有，量到的是谷底 -55.8 dB。移調增益因此變成 0.004，基頻被壓掉 48 dB。

八度剛好落在諧波上所以還行，三全音落進谷底就崩掉 —— 非單調就是這麼來的。

修法是給視窗一個下限 `0.6 * f0`（總寬 1.2·f0），保證一定涵蓋一根諧波。下限不能
再大，否則會抹平高頻細節（實測 2.5k~5k 的滾降在 0.6 時保住 18.0 dB，0.8 以上
開始變形）。

小號 32 音的 LSD 平均從 3.8 dB 降到 1.9 dB；鋼琴/提琴/長笛完全沒有變化，因為
它們的測試都在取樣八度內，從來沒踩到那些谷底。

## evaluate.py 的諧波取樣要跟著實際演奏的音高走

修完上面那個之後高音還是很差，但**移調距離為零**的單音測試也一樣差（G5 9.0 dB）
—— 這就不合理了，代表問題在尺而不是琴。

`harmonic_dist` 原本用十二平均律的理論頻率 `h * f0_nominal` 去取諧波，搜尋視窗
只有 ±27 Hz。可是真實演奏會偏音：小號 B5 的錄音基頻是 1006.5 Hz，比理論值
987.8 高 32 音分，到第 2 諧波就已經偏出 37 Hz，量到的全是諧波之間的谷底。

現在兩邊各自先用 `refine_f0()` 把基頻找準（在 ±6% 內找峰值 + 拋物線內插）再取
諧波。修正後 G5 從 9.0 掉到 3.3 dB、B5 從 9.6 掉到 4.8 dB，而且鋼琴/提琴/長笛
的數字也全部略有改善（移除了偏音造成的假誤差）。

**這件事的教訓跟前面「我自己的驗證方法也是錯的」是同一個**：拿到不合理的結果
時，要先懷疑量測而不是被測物。判斷依據是「移調距離為零卻依然很差」—— 那個
情況下被測物沒有可以出錯的地方。

## 非週期成分：管樂器聽起來不像的主因

用長笛素材調校時，前面那五個指標（包絡、衰減、LSD、頻譜圖、質心）全都很漂亮，
可是聽起來就是不像長笛 —— 像管風琴。把諧波之間的底噪量出來才看到問題：

    真實長笛 A4  -72.6 dB      合成  -99.5 dB      差 27 dB

長笛的「氣聲」就是那層底噪，少了它就只剩純音。原因是單位錯誤：分析器量到的
`noiseGain` 是**能量比**，合成端卻當成**振幅比**在用。能量比 0.004 對應的振幅是
sqrt(0.004) = 0.063，差了 16 倍。

修好份量之後還有第二個問題：位置。量真實長笛殘差（`x[n] - x[n-T]`）的頻譜分佈：

    0-0.9k 29.5%   0.9-2k 48.5%   2-5k 17.8%   5k 以上 4.2%

78% 緊貼著 f0/h2/h3 —— 它根本不是寬頻嘶聲，而是**每根諧波自己在微幅抖動**產生的
邊帶。所以現在的作法是：

| 殘差落點 | 合成方式 | 典型樂器 |
|---|---|---|
| 5·f0 以下（貼著諧波） | 對每根諧波做隨機幅度調變 `a_h * (1 + sigma * g)` | 鋼琴 2%、長笛 20% |
| 5·f0 以上 | 帶通白噪層（5~8·f0） | 提琴 89%（弓噪） |

比例不是寫死的，是 `analyzer.cpp` 的 `noiseHighFraction()` 量出來的。起音瞬態同樣
量一份 `attackHighFrac` 再拆 —— 真實鋼琴的起音殘差 93% 在 1.3 kHz 以下、3 kHz 以上
是 0，早期版本一律用寫死的 9 kHz 寬頻，等於在每個鋼琴音頭噴一團它沒有的高頻嘶聲。

### 撥弦樂器把第三個問題逼出來了：在哪裡量

加吉他素材的時候，九個指標裡有八個一開始就很漂亮（LSD 全部 < 1.5 dB、質心 0.98），
只有噪聲量誤差是 **+6.1 dB**，最糟的一個音 +12 dB。合成出來的每個吉他音都掛著一層
真實吉他沒有的嘶聲，而 LSD、頻譜圖、質心三個指標對它完全沒有反應 —— 它們本來就
看不到 −70 dB 的東西。這正是當初加這兩欄的理由。

追下去發現不是合成端的問題：合成器忠實地照 `noiseGain` 送出噪聲，是 `noiseGain`
量錯了。殘差比在一個音之內差很多：

| 撥弦後 | 電平 | 30 ms 殘差比 |
|---|---|---|
| 0.1 s | −2.5 dB | 0.90% |
| 0.3 s | −3.5 dB | 0.45% |
| 0.6 s | −5.6 dB | 0.038% |
| 1.5 s | −8.4 dB | 0.017% |
| 5.0 s | −20.4 dB | 0.13%（已經是錄音本底） |

分析器沿著「本體」取 5 點取中位數，而衰減型樂器的本體很短 —— 這批吉他是 0.19~0.48
秒、鋼琴更短，只有 0.11~0.16 秒。5 個點於是全部落在撥弦的餘波裡，量到的是起音，
不是持續段。而起音那一段本來就有 `attackNoise` 在負責（前 150 ms），等於重複計算。

改法是把持續段的取樣視窗往後挪：起音後 0.35 秒開始、量到電平掉到峰值 −25 dB 為止
（再低下去量到的是房間不是樂器）。**只對衰減型套用** —— 持續型的本體就是持續段本身，
實測把它們一起往後挪，噪聲落點誤差反而全部變差 0.3~1.0 個百分點，因為視窗尾端會
吃進收弓／收氣那一段。`decaying` 是從包絡量出來的連續量（本體佔音長 < 25% 且峰值
在前 25%），`release` 與衰減率早就用同一個量在分流，不是新加的樂器分支。

結果：吉他噪聲量誤差 +6.1 dB → +0.7 dB，噪聲位置 10.2 → 7.6 pt。

### 順帶把兩件事修掉

**週期長度要現找。** 撥弦之後音高會漂（分析器自己就報過這批素材「音高擺動
48~57 cents」），用整段平均的 f0 去算 `x[n]-x[n-T]`，剩下的可能是相位對不上而不是
雜訊。改成在 ±3% 內掃 7 個候選、取殘差最小的那個 —— 定義上量的是「用附近任何一個
週期都解釋不掉的能量」。對真的有寬頻噪聲的樂器沒有影響（換 T 也解釋不掉白噪聲），
但對有顫音的樂器有：小號質心相關性 0.738 → 0.766、頻譜圖 1.50 → 1.49，
小提琴頻譜圖 1.81 → 1.73。

**抖動層的補償少了一個係數。** 修好視窗之後，四種樂器的噪聲量誤差整齊地落在
−2.0 ~ −3.3 dB（長笛 −3.1、鋼琴 −2.9、小號 −3.3、提琴 −2.0）。四種樂器、四種音域、
同一個方向、同一個量級 —— 那是補償鏈少了一項，不是四次巧合。補償鏈上本來就有兩個
承認過的一階近似（邊帶平均增益的解析式、內插衰減 0.83），`TC_JITTER_CAL = 1.9`
把剩下的差補起來。只作用在抖動層：寬頻噪聲層是不相關雜訊，週期差分對它沒有損失。

## 移調：第二個八度為什麼會走味

音色庫涵蓋不到的音靠移調，而半音階的上半段整整高一個八度。實機聽起來
「第二個八度開始失真」，量出來也確實如此。

這件事以前**量不到**：bench 只評測「有對應素材的音」，而長笛、鋼琴、提琴的
素材剛好就是音色庫那 12 個音 —— 上半個八度沒有參考，指標從來沒看過它。
小號有 E3~B5 共 32 個音，所以可以做這個實驗：**只用 C4~B4 建音色庫、演奏到
B5，再拿真實的 C5~B5 素材去對照**（`tools/sim/xrange` 就是為這件事寫的）。

|  | LSD 起音 | LSD 中段 | LSD 尾段 | 質心相關性 |
|---|---|---|---|---|
| 第 1 八度（音色庫涵蓋得到） | 1.14 | 0.66 | 0.84 | 0.924 |
| 第 2 八度（往上移調一個八度） | 2.30 | 1.53 | 1.34 | 0.705 |

先排除幾個常見嫌疑：**沒有混疊**（0.45·fs 以上只有 0.002%）、**沒有削波**
（峰值 0.21~0.37）、**非諧波能量 < 1%**。而且**平均質心是對的** ——
合成/參考 = 0.99，共振峰校正確實有效。錯的是**隨時間的變化**：
質心相關性從 0.92 掉到 0.71，LSD 起音整整翻倍。

### 成因：搬對了振幅，搬錯了時間軌跡

舊的移調寫法是：

```c
float g = specEnvGain(fNew) / specEnvGain(fRef);   // 頻譜包絡在新舊頻率的增益比
ampOut[h] = raw[h] * g;                            // 來源第 h 根 × 靜態增益
```

`g` 是靜態的，所以目標第 h 根的**時間變化完全來自來源第 h 根**。可是往上移調
一個八度時，目標的第 h 根落在來源第 **2h** 根的頻率上 —— 該跟著走的是第 2h 根
的起伏（高次諧波進得晚、衰減得快），不是第 h 根的。平均值被包絡校正救回來了，
時間軌跡沒有。

### 作法：在目標的諧波頻率上重新取樣來源

```c
const float hSrcF = fNew / prof->f0 - 1.0f;   // 目標第 h 根落在來源的第幾根
// 對數域內插 raw[floor] 與 raw[ceil]
```

也就是直接問「來源在這個絕對頻率上有多大聲」。共振峰自然留在原位（這本來就是
共振峰保留的定義），而且拿到的是**那個頻率**的時間軌跡。超出量測到的 32 根之後
仍然用包絡外推，跟第 33 根以上的邏輯一致。

### 權重跟著移調距離走

重取樣不是免費的：非八度的移調會落在兩根諧波之間，內插到的可能是「谷底」而不是
包絡；舊作法用平滑過的包絡沒有這個漣漪。而且**移調越少，代價越大而好處越小**——
音色庫涵蓋得到的音，演奏音高與 profile 只差幾個 cent，但第 30 根諧波的索引已經
偏了 0.12。實測那些音如果也走重取樣，吉他的 LSD 中段會從 0.59 掉到 0.85，
純粹是內插漣漪，沒有換到任何東西。

所以權重依移調距離：**1 個半音以內完全不用，4 個半音以上完全用**
（`TC_TRANSPOSE_RESAMPLE_LO/HI`）。

### 結果

| 小號，音色庫 C4~B4 | LSD 起音 | LSD 中段 | LSD 尾段 | 質心相關性 |
|---|---|---|---|---|
| 第 1 八度 舊 → 新 | 1.14 → **1.14** | 0.66 → **0.66** | 0.84 → 0.84 | 0.924 → **0.924** |
| 第 2 八度 舊 → 新 | 2.30 → **1.79** | 1.53 → **1.23** | 1.34 → **1.18** | 0.705 → **0.771** |

第 1 八度**逐位元不變**（移調距離小於 1 個半音，權重是 0）。

反方向也驗過 —— 用 C5~B5 建音色庫、往下移調演奏 C4~B4：
LSD 起音 3.06 → 2.30、中段 2.32 → 1.99、尾段 2.34 → 2.17。

五樂器 bench 的代價：長笛、鋼琴、提琴、吉他都在四捨五入以內；小號因為
16 格音色庫要涵蓋 32 個音，有些音移調得比較遠，LSD 三項各差 0.02~0.03
（2.16→2.19、1.45→1.48、1.65→1.67），但包絡相關性從 0.211 升到 0.219。
拿第二個八度 20% 的改善換這個，划算。

**還沒解決的**：第 2 八度的 1.79 仍然比第 1 八度的 1.14 差。剩下的差距多半在
起音的時間結構 —— 實測小號的起音時間隨音高**變長**（C4 139 ms、G5 238 ms），
而 `harmOnset` 是照搬來源的，沒有跟著音高走。要再進一步就得把起音時間也建模。

## 顫音：量週期性，不是量離散度

舊版拿「9 個 YIN 候選的離散度」當顫音深度。那會同時收進演奏者的緩慢音高漂移、
YIN 自己的估計誤差、還有偶發的八度誤判 —— 標示 **nonvib**（無顫音）的長笛素材被
量出 2.3~11.5 cents 的顫音，合成時就加上素材裡沒有的擺動。

現在改成量「4~8 Hz 的週期性調變」：f0 外差解調取出瞬時頻率軌跡 -> 扣掉 0.5 秒移動
平均去掉漂移 -> 在 3~9 Hz 掃 DFT，只有當這個頻帶佔殘差變異數 25% 以上才認定是顫音。

解調的累加窗長要取 f0 週期的整數倍，否則第二諧波會洩漏進基帶（長笛 A4 的 h2 比基頻
還強），本底會高到 35 cents，連 30 cents 的顫音都會被蓋掉。

驗證方式是造已知答案的檔案（陽性對照）加上真實素材（陰性對照）：

| 測試 | 植入 | 量到 |
|---|---|---|
| 陽性 | 12 cents @ 6.5 Hz | 12.0 cents @ 6.5 Hz |
| 陽性 | 30 cents @ 5.0 Hz | 30.6 cents @ 5.0 Hz |
| 陽性 | 60 cents @ 4.5 Hz | 59.5 cents @ 4.5 Hz |
| 陰性 | Flute.nonvib | 無顫音 |
| 陰性 | Violin.arco（這批確實沒顫音） | 無顫音 |
| 陰性 | Piano | 無顫音 |

## 音色庫滿了要犧牲誰

`TC_MAX_PROFILES` 是 16。素材超過 16 個的時候，舊版直接拒收 —— 看起來安全，
其實是把結果交給**檔名排序**決定。

32 個小號素材（E3~B5）依檔名載入的順序是 A3 A4 A5 Ab3 Ab4 Ab5 B3 B4 B5 …
跟音高完全無關，所以前 16 個留下來的是：

```
舊版：Ab3 A3 Bb3 B3 C4 D4 Ab4 A4 Bb4 B4 C5 D5 Ab5 A5 Bb5 B5
      最大間距 6 個半音，音域 27 個半音，E3~G3 整段沒有素材
新版：最大間距 3 個半音，音域 31 個半音（E3 有進來）
```

後果實測（`tools/bench.py`，小號 32 音）：

| 指標 | 舊版 | 新版 |
|---|---|---|
| LSD 起音 | 12.0 dB | **2.2 dB** |
| LSD 中段 | 12.5 dB | **1.4 dB** |
| LSD 尾段 | 12.7 dB | **1.6 dB** |
| 頻譜圖 MAE | 4.4 dB | **1.5 dB** |
| 質心相關性 | 0.627 | **0.742** |
| 噪聲量誤差 | +18.9 dB | **−3.4 dB** |
| 噪聲位置 | 14.8 pt | **9.9 pt** |

LSD > 8 dB 是「音色明顯不同」，所以舊版在低音區根本不是小號。

### 取捨規則

滿了之後不是拒收，而是找一個**冗餘的內部點**換掉：

- 目標函數是**間距平方和**（半音為單位），越小代表分佈越平均。
- **端點不參選**：音域的最低與最高一旦被犧牲，超出去的音就只能外推，
  那比內插差得多。
- 新音高**擴大音域**就一律收；落在範圍內則要「平方和真的下降」才換。
  相等不換 —— 沒有好處的替換只會讓結果又變成跟載入順序有關。

一個踩過的坑：第一版目標函數用「最大間距」，結果卡在 6 個半音，跟舊版一樣爛。
原因是最大間距有一大片**平台**：很多次替換算出來完全相同，而「只有嚴格變好
才換」就永遠不動。平方和沒有平台 —— 只要把能量從大間距搬到小間距它就下降。

另一個坑：第一版用「跟鄰居最擠的那個」當犧牲者，log 裡出現
`349.2 Hz 換掉 174.6 Hz`，而 174.6 Hz 是它前一步才剛收進來的。
每一步各自看起來合理，合起來卻在原地繞。桌機測試兩次都當場抓到。

規則本身在 `make evict_test`，含真實的 32 個小號素材情境與舊版邏輯的負對照。

## 多樂器回歸基準：tools/bench.py

改合成程式碼最危險的不是「沒有變好」，而是**某一種樂器變好、另一種悄悄變差**。
只看一種樂器的數字永遠發現不了。

```bash
cd tools
python3 bench.py --lib /path/to/聲音庫 --save baseline.json   # 改之前存基準
# ...改程式碼...
python3 bench.py --lib /path/to/聲音庫 --compare baseline.json
```

`--compare` 會逐項比對，變好標 `+`、變差標 `-`，最後把所有退步的項目列出來。

都是程式碼造成的，不需要跑統計。

## 非諧性：把「音高估錯」誤判成弦的剛度

小提琴合成出來有一層沙沙聲。拆下來看，`BANK.BIN` 裡小提琴的非諧性係數
B 高達 **0.00035** —— 那是鋼琴的量級（實測鋼琴 0.00028~0.00033），
提琴物理上應該接近 0。B = 0.00035 時第 20 根諧波偏高 **113 cents**、
第 32 根偏高 265 cents，三聲部一起響就互相打拍。

### 成因：一條式子把兩件事混在一起

舊版對每根諧波各算一個 B 再平均：

```c
float ratio = (exactBin * binHz) / fh;          // fh = (h+1) * f0
float B     = (ratio * ratio - 1.0f) / ((h+1) * (h+1));
```

f0 若估偏 δ，**每一根**諧波看起來都偏高同樣的比例，`ratio² − 1 ≈ 2δ` 對所有 n
都一樣；除以 n² 之後仍然是正的，平均起來就成了一個假的正 B。而最後那道
`tc_clampf(..., 0.0f, 0.002f)` 下限是 0 —— 負值被夾掉、正值留著，偏差是**單向**的。

### 作法：同時擬合常數項與 n² 項

```
    ratio² − 1  =  c  +  B · n²
                   ↑     ↑
                   │     └── 真的非諧性：偏移量隨 n² 成長
                   └──────── f0 估偏：對所有 n 都一樣的常數
```

這是以 x = n² 為自變數的一元線性迴歸。c 把音高誤差整個吸收掉，B 因此對 f0
的估計誤差免疫。再加一道顯著性檢定：只有 B > 2×標準誤才採信，否則判 0。

### 順帶挖出來的第二個 bug

修好估計式之後，**鋼琴的 B 反而全部變成 0** —— 這才發現峰值搜尋窗只有 ±2 bin
（±43 Hz）。鋼琴 C4 的第 12 根諧波在 B = 0.0003 時要偏高 67 Hz，超出窗外，
搜尋只能停在窗邊，位移被截斷。**舊版之所以對鋼琴「量得準」，是因為估計式偏高、
搜尋窗又把位移截短，兩個錯誤剛好抵銷。**

所以搜尋半徑改成跟著可能的位移走（`TC_PEAK_WIDE`）：

```c
rad = min( 0.035 * fh / binHz ,  0.45 * f0 / binHz )   // 3.5% 的位移；上限是半個諧波間距
```

### 結果

| 樂器 | 修正前 B | 修正後 B |
|---|---|---|
| 小提琴 | 0 ~ **0.00035** | 全部 0 ✓ |
| 小號 / 長笛 | ~0 | 全部 0 ✓ |
| 鋼琴 | 0.00028 ~ 0.00033 | 0.00006 ~ 0.00031（12 音中 5 音顯著）✓ |
| 吉他 | 0.00000 ~ 0.00007 | 0.00006 ~ 0.00027 |

指標變化（跟三階低通那一版比）：

| 樂器 | LSD 起音 | LSD 中段 | LSD 尾段 | 噪聲位置 | 噪聲量 |
|---|---|---|---|---|---|
| 小提琴 | 1.6 → **1.1** | 1.7 → **0.9** | 2.5 → **1.8** | 15.1 → **13.0** | −1.0 → −2.3 |
| 小號 | 2.2 → 2.2 | 1.5 → **1.1** | 1.7 → **1.3** | 8.5 → **5.9** | −2.9 → −4.0 |
| 鋼琴 | 1.4 → 1.5 | 1.3 → 1.3 | 2.4 → 2.5 | 11.5 → 12.8 | −1.8 → −1.8 |
| 長笛 | 1.1 → **1.0** | 0.7 → 0.7 | 0.8 → 0.8 | 7.6 → **7.5** | −2.2 → −2.3 |

用實機存下來的 `BANK.BIN` 重算卡農，2~6 kHz 的粗糙度從 0.168 降到 **0.142（−16%）**。

**噪聲量退步是要說清楚的一件事。** 假的非諧性會讓合成出來的諧波不再滿足
x[n] ≈ x[n−T]，於是被週期差分法**當成非週期成分算進去**。換句話說，它一直在
替噪聲層補一份它自己沒發出來的量。拿掉之後，噪聲層真正的不足才露出來
（提琴 −2.3 dB、小號 −4.0 dB）。這是「兩個錯誤互相抵銷」的第三個例子，
也是下一項該修的東西 —— 但不該用調大抖動來蓋掉：實測把 `TC_JITTER_CAL`
從 1.9 拉到 3.2 確實能把噪聲量補回來，代價是噪聲位置整組退步
（提琴 13.0 → 15.0、鋼琴 12.8 → 14.1），等於把噪聲塞回錯的頻帶。

## 弓噪的落點：一階低通關不住

小提琴的「噪聲位置」一度是五種樂器裡最差的（18.5 pt，判讀標準是 < 8 很好、
< 15 可接受）。把非週期成分拆成 4 個頻帶就看得很清楚（單位百分點）：

```
                0-0.9k   0.9-2k    2-5k     5k+
  素材            21.9      9.8    61.6     6.7
  一階低通(舊)    25.7     10.2    35.3    28.9     <- 少 26 點弓噪，多 22 點嘶聲
  三階低通(新)    26.3     13.1    41.2    19.5
```

真實小提琴的弓噪有 62% 集中在 2~5 kHz，5 kHz 以上只有 6.7%。舊版合成只有
35% 落在 2~5 kHz，卻有 29% 灑在 5 kHz 以上。

成因是噪聲層的低通只有一階：A4 時截止在 3.5 kHz，但 6 dB/oct 的裙邊到
7 kHz 才衰 6 dB、14 kHz 才衰 12 dB，白噪聲餵進去自然留一大堆高頻。
改成三階（18 dB/oct）之後，四種樂器的噪聲位置**全部單調改善**：

| 級數 | 長笛 | 鋼琴 | 小號 | 小提琴 |
|---|---|---|---|---|
| 1（舊） | 8.5 | 12.9 | 9.8 | 18.5 |
| 2 | 7.7 | 11.9 | 8.9 | 16.0 |
| **3** | **7.6** | **11.5** | **8.5** | **15.1** |
| 4 | 7.6 | 11.3 | 8.4 | 14.6 |
| 6 | — | — | — | 14.0（8 級反而回到 14.4） |

取 3 級是因為那是曲線的膝點。殘留的約 14 點不是斜率問題 —— 再陡也降不下去，
那是帶通的中心與形狀還不夠貼，要改的是 `fHi`/`fLo` 怎麼從量測值決定，
不是再加級數。

兩個實作細節：

* **每級的截止要先補償。** N 個相同的一階極點串接後，−3 dB 點會掉到
  `fc·sqrt(2^(1/N) − 1)`（3 級是 0.5098）。不補償的話就變成「同時改了裙邊
  陡度和轉角位置」兩件事，分不出哪一項在起作用。所以每級先除以那個係數。
* **`noiseNrm` 的校正迴圈也要跟著串接。** 那 1024 個取樣的實測是用來補回
  濾波器的 RMS 增益的；只改渲染路徑而忘了改校正，噪聲的**量**會整體跑掉。

代價：每級每個取樣點 2 個浮點運算，8 複音下約 0.7 MFLOP/s，可以忽略。

> **後續（2026-08-26）**：上面那句「殘留的約 14 點是帶通的中心與形狀還不夠貼」
> 猜對了，但一階遞迴串接這個結構本身也是錯的 —— 見下一節。現在低通是
> 3 級 biquad（`TC_NOISE_LP_STAGES`），上緣改由 `specEnv` 決定。

## 起音沙沙聲：噪聲層被放在樂器完全空白的頻段

症狀：卡農的前兩個音（旋律最高的兩個音）起音有明顯的沙沙聲。把寬頻噪聲層
關掉就完全消失，但只把它的音量降到 1/4 卻沒有用 —— 這一組現象排除了「份量
太大」，指向「位置不對」。

**兩個獨立的量測**把位置釘死：

一、**真實素材的殘差落在哪裡（絕對頻率，跟音高無關）。** 對聲音庫裡每一個音
算週期差分殘差，取能量的 10/50/90 百分位：

| 樂器 | p10 | p50 | p90 | 這個範圍隨 f0 變動嗎 |
|---|---|---|---|---|
| 鋼琴 | 206 | 493 | 1849 Hz | 幾乎不變（f0 262→494 Hz） |
| 長笛 | 673 | 1456 | 3326 Hz | 幾乎不變 |
| 小提琴 | 388 | 2036 | 3714 Hz | 幾乎不變（f0 196→988 Hz） |
| 小號 | 1047 | 1494 | 2519 Hz | 幾乎不變（f0 165→988 Hz，2.5 個八度） |

殘差的落點是**樂器本體的性質**，不是音高的函數。可是舊版的帶通是
`5*f0 ~ 8*f0` —— 小號從最低音到最高音，這個帶通會從 824–1320 Hz 一路搬到
4939–7904 Hz，整整六倍，量測結果完全不支持。

二、**噪聲層與樂器自己的能量比（in-situ，起音 120 ms 內，逐頻帶）。**
用 `TC_NOISE_BB_GAIN=0` 對照 `=1`（迴圈照跑、亂數照消耗，兩份相減就是這一層）：

```
                0-900   900-2000  2000-5000  5000 Hz+
  鋼琴 舊       -44.7      -21.5      -10.1     +18.9   <- 噪聲比鋼琴自己還大 19 dB
  鋼琴 新       -42.3      -18.6      -17.2     -13.4
```

鋼琴 F#5 的噪聲層被放在 3.7–5.9 kHz，而鋼琴自己的頻譜包絡在 2.5 kHz 就掉到
−40 dB、5 kHz 是 −67 dB。那層噪聲落在樂器**完全空白**的頻段，沒有任何東西
遮蔽它 —— 聽起來就是沙沙聲。這也解釋了為什麼降音量沒用：降 12 dB 之後它還是
比鋼琴的諧波大 7 dB。

**修法**：帶通的上緣改成「這件樂器自己的頻譜包絡掉到峰值 −35 dB 的頻率」。
`specEnv` 分析時就量好了、也早就存在 `BANK.BIN` 裡，所以**這個改動不用重跑分析**。
量到的落點：

| 樂器 | 上緣 fHi |
|---|---|
| 鋼琴 | 2.3 ~ 3.4 kHz |
| 吉他 | 3.7 kHz |
| 長笛 | 4.9 kHz |
| 小提琴 | 6.4 kHz |
| 小號 | 7.0 kHz |

順序跟上面那張百分位表一致 —— 兩個互相獨立的量測指向同一件事，這才敢改。

下緣仍然是 `5*f0`（更低的殘差由諧波抖動負責），但夾在 `fHi/2` 以下：高音區的
`5*f0` 常常已經在樂器的頻譜之外，硬撐會把帶通壓成一個沒有通帶的空殼，
底下的 RMS 正規化再把剩下那一點點放大好幾倍。**上一版「每級轉角上限 3 kHz」
就是踩到這個坑** —— 它確實把 5 kHz 以上的漏出壓下去了，卻同時把整個帶通拖到
834–3475 Hz，於是沙沙聲換了個頻率繼續存在（實測 4000 比 3000 亮，但兩者都還在響）。

濾波器同時從「一階遞迴串接」換成 **biquad**。一階遞迴 `y += c*(x−y)` 在
`c → 1` 時就等於 `y = x`；`c = 1 − exp(−2π·fc/fs)`，高音區把每級轉角推到
15 kHz 時 `c = 0.89`，所謂的三階低通根本沒有在濾波。雙線性轉換的 biquad
不會有這個退化，3 級（36 dB/oct）才擋得住 5 kHz 以上的漏出。

門檻取 35 dB 的理由 —— 起音 5 kHz 以上殘差**絕對位階**的誤差（dB，越小越好）：

| 門檻 | 鋼琴 | 小提琴 | 長笛 | 小號 | 平均 |
|---|---|---|---|---|---|
| 舊版 | 15.2 | 1.6 | 3.6 | 15.1 | 8.9 |
| 30 | 6.4 | 1.5 | **14.3** | 14.6 | 9.2 |
| **35** | **5.1** | **2.3** | **5.7** | 15.4 | **7.1** |
| 40 | 2.6 | 3.3 | 3.3 | 16.8 | 6.5 |

30 dB 對鋼琴最安全，但會把長笛的氣聲砍掉 14 dB —— 那是長笛之所以像長笛的東西。
35 dB 是四種樂器都在 6 dB 以內的唯一一格。小號那 15 dB 不是這一層造成的
（`TC_NOISE_BB_GAIN=0` 一樣是 15 dB），是起音抖動層的問題，還沒動。

回歸基準（噪聲位置，pt，越小越好）：

| | 長笛 | 鋼琴 | 小號 | 小提琴 |
|---|---|---|---|---|
| 舊 | 8.3 | 12.3 | 5.5 | 12.1 |
| 新 | 8.6 | **12.2** | 6.1 | **7.1** |

小提琴大幅改善，鋼琴持平，長笛與小號各退 0.3 / 0.6 點 —— 誠實記下來：
這兩個是拿它們換小提琴與鋼琴的起音乾淨度。其餘八個指標的變動都在捨入誤差內。

代價：每取樣點多 3 個 biquad（4 級共 20 個乘加），8 複音下約 1.8 MFLOP/s。

### 量這件事的工具：`tools/resid_pos.py`

`evaluate.py` 的「噪聲位置」量的是殘差在四個頻帶的**分佈**（百分比），
那是相對量；沙沙聲卻是絕對量的問題 —— 某個頻帶的噪聲比樂器自己還大聲。
分佈對了不代表位階對了，上面那 19 dB 就是這樣藏起來的。

`resid_pos.py` 補這個洞，輸出兩種東西：殘差能量的 10/50/90 百分位頻率，
以及各頻帶殘差相對整段能量的絕對位階（dB），素材與合成並排。

```
python3 tools/resid_pos.py --lib <聲音庫>
python3 tools/resid_pos.py --lib <聲音庫> --inst piano --syn out.wav --start 60 --count 24
```

順帶修掉 `evaluate.py` 的一個靜默失敗：參考素材只 glob 小寫的 `*.wav`，
而韌體自己寫出來的是全大寫（`REC.WAV`、`T_C4.WAV`）。用機器自己錄的素材
評測時整批會被跳過，錯誤訊息卻是「找不到能配對音高的參考素材」，
看起來像檔名格式不對。`聲音庫/test/` 那 12 個音一直評不出來就是這個原因。

## 包絡相關性量不到的兩種情況

**一、參考包絡太平。** 被比對的那段窗內，對數包絡的標準差實測：

| | 標準差 |
|---|---|
| 小提琴 | 12 ~ 26 dB |
| 鋼琴 | 7 ~ 10 dB |
| 長笛 | 2.0 ~ 2.1 dB |
| 小號 | 2.1 dB |

持續音本來就該平。兩條近乎水平的曲線算 Pearson r，結果完全由顫音與呼吸噪音的
隨機起伏決定 —— 那正是合成器不該也無法逐點重現的東西。

所以標準差低於 3 dB 就回報「量不到」（`ENV_FLAT_STD_DB`），不要給一個看起來
像分數的雜訊。這條在小號身上救回一次假警報：音色庫的修正讓 LSD 從 12.5 掉到
1.4 dB，env_r 卻從 0.145 掉到 0.058 —— 兩個都是雜訊，差異沒有意義。

**二、參考素材比樂譜的音長還短。** 小提琴素材實測音長 1.02~2.11 秒，
而半音階每個音是 1.818 秒。參考在 1.2 秒就收弓了，合成器卻照樂譜holding 到 1.818 秒 ——
包絡當然對不上。這是**樂譜音長**與素材不匹配，不是音色複製本身的問題。
要公平比較得讓樂譜的音長跟著素材走，那是還沒做的事。

## 為什麼不照樂器種類分不同程式碼

看起來很誘人，但這批素材證明「類別標籤」沒有想像中可靠：12 個 Violin.arco 樣本其實
完全沒有顫音（兩種獨立方法都驗過），照「弦樂=有顫音」去套反而會加錯東西。而且使用者
拿麥克風錄一個沒被分類過的樂器時，分支式的寫法就沒有路可走。

現在的作法是：**程式路徑只有一條，差異全部由量測到的連續量驅動**。
例如殘差落在 5·f0 以上的比例，鋼琴 2% / 長笛 20% / 提琴 89% —— 這個量本身就把三者
分得很開，不需要先貼標籤。

## 成品：PLAY.WAV 與 CANON.WAV

`t` 訓練完會自動演奏並把成品寫成 SD 卡上的 `PLAY.WAV`（44.1 kHz 立體聲
16-bit，約 47 秒 8 MB）。也可以隨時按 `w` 手動錄一次。

卡農另外存成 `CANON.WAV`（按 `j`，約 45 秒 8 MB）。**兩份分開存**是刻意的：
`PLAY.WAV` 是評測流程的輸入，被卡農蓋掉的話得整個重錄一次，而且不會有任何提示。
反覆試聽時用 `j n`，只演奏不寫檔。

**錄到的就是聽到的那份訊號**——擷取點接在輸出混音器之後（合成器 → reverb →
混音器 → 耳機／擷取），所以檔案內容 100% 由加法合成器產生，**沒有任何一個
音符是原始錄音的取樣播放**。原始素材只被用來萃取音色指紋，從來不會被播放。

演奏開始時序列埠會明確宣告音源：

```
[PLAY] 音源：加法合成器（最多 64 諧波 + 噪聲層），音色庫 12 組
[PLAY] 音色來源：MLP 模型（已訓練）
```

若 SD 上有 `MODEL.BIN` 卻沒載入成功，這裡會警告你按 `m` 重試，不會默默退回
關鍵影格模式讓你以為聽到的是訓練結果。OLED 右上角也一直顯示 `MLP` 或 `KEYFR`。

寫入速率 176 KB/s。用 Teensy 4.1 內建 SDIO 插槽輕鬆負荷；若用 Audio Shield 的
SPI 插槽可能掉格，掉格會在結束時回報，OLED 上也會顯示 `DROP!`。

## shimmer 在高音區被判成 0：本體視窗太短

高音區合成出來像管風琴，追下去是 `shimmerDepth` 整片歸零。

### 成因

shimmer 的取樣窗原本綁在「本體」（`susA..susB`）上，而本體對小提琴來說又晚又短
—— 這件事程式裡早就寫著：「小提琴常常是漸強，本體因此又晚又短，實測 G4 的本體
只佔 15%」。高音的素材更短，於是本體只剩十幾格：

| 音 | 本體 | 佔音長 | 可用格數 | 結果 |
|---|---|---|---:|---|
| B3 | 0.26~1.25 s | 57% | 79 | 正常 |
| F4 | 0.30~1.27 s | 65% | 76 | 正常 |
| C5 | 0.63~1.20 s | 45% | 42 | 正常 |
| G#5 | 0.92~1.13 s | 18% | 19 | **< 24 → 判 0** |
| B5 | 0.77~1.02 s | 21% | 23 | **< 24 → 判 0**（差一格） |

### 作法

shimmer 量的是「除以 9 格（104 ms）局部移動平均之後剩下的抖動」，那個去趨勢
本來就會把漸強、漸弱、任何比視窗慢的形狀完全消掉。**限制在本體內對量測沒有
幫助，只是白白少掉格數。** 所以把起點往前拉到起音後 `TC_SHIM_START_SEC`（0.15 s）。

**只延伸起點，終點一定留在本體結束。** 試過把終點也放到 `offset`：格數從 19
變成 89，可是合格諧波數反而垮掉（B3 從 9 掉到 1）—— 「衰減太快就不列入」那道
閘門拿窗尾跟窗頭比，一旦吃進收弓的 release，`last/first` 必然小於 0.25，
於是每根諧波都被剔除。本體的終點本來就是「收弓開始」，那個判定是對的。

只對持續型放寬。衰減型（鋼琴/撥弦）維持原樣 —— 往前拉會吃進起音後那段極快的
衰減，而 shimmer 當初改寫成對數域移動平均，正是為了修掉鋼琴被誤量成 22.6% 的
假抖動。實測鋼琴與小號的所有指標一個位元都沒變。

### 上限從 0.20 收到 0.12

放寬視窗之後 Ab5/B5 量出 0.20~0.26，整片撞上限。那不是一兩根諧波的離群
（改用跨諧波中位數也一樣高，B5 的中位數 0.248 比平均還高），是整個分佈都高
—— 那兩個錄音本身就不穩定。撞上限的值會在合成端灌進過量的振幅調變：

| 上限 | 小提琴質心相關性 | 噪聲位置 |
|---|---|---|
| 0.20 | 0.650 | 10.8 |
| 0.15 | 0.669 | 10.8 |
| **0.12** | **0.700** | **10.7** |

（原本沒修時是 0.690 / 10.8。）0.12 也比 0.20 更貼近本檔「真實樂器約 5~10%」
的說法。

### 結果與殘留問題

小提琴 LSD 起音 1.75→1.71、中段 1.33→1.30、尾段 2.65→2.60、質心 0.690→0.700；
鋼琴與小號完全不變。包絡相關性 0.113→0.092，但那個指標對小提琴本來就沒有意義
（樂譜音長 1.818 s vs 素材 1.02~2.11 s，見「交接說明」）。

**還沒解決**：C5 以上四個音現在全都停在 0.12 的上限上。也就是說高音區的
估計值仍然不可信，只是從「假的 0」換成「合理的常數」。要真的量準，得先弄清楚
為什麼高音素材的逐諧波起伏普遍偏高（錄音本身不穩定？高音區的諧波萃取有偏差？）。
`TC_SHIM_MAX` 這個數字是拿現有四種樂器掃出來的，換一批素材未必還是最佳值。

除錯用：`-DTC_SHIM_DEBUG=1` 會印出每根諧波的採納/剔除原因與格數，
上面那張表就是這樣量出來的。

## 把 SD 掛成電腦的磁碟機（USB MTP）

預設情況下，要把 `PLAY.WAV`、`CANON.WAV`、`BANK.BIN` 帶回電腦只有一條路：
拔卡、插到讀卡機。遠端維護時這是整個流程裡唯一卡死的環節 —— 韌體可以遠端燒、
素材可以遠端分析、模型可以遠端訓練，就是成品拿不回來。

開啟 USB MTP 之後，SD 卡會直接出現在電腦的檔案總管裡。

### 怎麼開

1. Arduino IDE → **Tools → USB Type → `Serial + MTP Disk (Experimental)`**
2. 安裝 [MTP_Teensy](https://github.com/KurtE/MTP_Teensy) 函式庫（Teensyduino
   **沒有**內建，要自己裝）
3. 重新編譯上傳

程式碼不用改。`config.h` 的 `TC_HAS_MTP` 會偵測 USB Type 帶進來的
`USB_MTPDISK` / `USB_MTPDISK_SERIAL`，沒選對就整段編譯掉 —— 所以同一份原始碼
在普通的 `Serial` USB Type 下照樣編得過，不會因為少裝一個函式庫就整包壞掉。

### 為什麼不是無條件開著

PJRC 在 Teensyduino 1.57 的公告裡自己寫了：「要讓 MTP 與 Teensy 同時存取檔案
還有很多工作要做」。MTP_Teensy 的
[issue #41](https://github.com/KurtE/MTP_Teensy/issues/41) 更具體：MTP 掛載期間
寫 SD 會逾時失敗，而且**內建 SD 槽比 Audio Shield 的 SPI 槽更嚴重**。

本專案剛好踩在最糟的組合上：`tcSdBegin()` 優先用內建 SDIO 槽，而演奏時的寫入
是 44.1 kHz 立體聲即時串流，漏一個 block 就是成品裡的一個爆音。

所以設了三層防線：

| 防線 | 作法 |
|---|---|
| 編譯期 | `TC_MTP_DEFAULT_ON` 決定開機後預設開不開 |
| 執行期（自動） | `loop()` 只在**完全閒置**時呼叫 `MTP.loop()` |
| 執行期（手動） | 序列埠 `u` 指令當場開關 |

第二層是關鍵。監看、採樣、麥克風錄音那三段在 `loop()` 裡各自 `return` 掉了，
分析與訓練是阻塞呼叫（那段期間 `loop()` 根本沒在跑），所以唯一需要明確擋掉的
是「演奏並擷取」：

```cpp
if (gMtpOn && !gPlayer.playing() && !gCap.active()) MTP.loop();
```

代價是這些期間電腦上的磁碟機會沒有回應。這是刻意的取捨：寧可讓檔案總管
轉圈圈，也不要在成品裡留下一個掉 block 的爆音。

### 演奏完要自己按 F5

原本的設計是寫完 WAV 之後送一次 `MTP.send_DeviceResetEvent()` 通知主機檔案變了。
**做不到。** MTP_Teensy 把所有 `send_*Event()` 包在 `#if USE_EVENTS == 1` 裡，
而那個巨集在函式庫自己的編譯單元裡是關的，名稱查找於是落到私有區那份同名宣告：

```
error: 'int MTP_class::send_DeviceResetEvent()' is private within this context
```

錯誤訊息會誤導人 —— 它講的是存取權限，實際原因是那份公開宣告根本沒被編進去。
在 `.ino` 裡 `#define USE_EVENTS 1` 沒有用：Arduino 的函式庫是獨立編譯的，
草稿碼的巨集傳不進去。要開就得改函式庫本身，那會讓專案綁在一份手改過的
MTP_Teensy 上，換台電腦就編不出來。

實際影響很小：MTP 在演奏期間本來就沒有被服務，所以主機不可能快取到寫到一半的
大小。**演奏結束後在檔案總管按 F5** 就會看到正確的檔案。

### 編譯涵蓋

MTP 那段程式碼包在 `#if TC_HAS_MTP` 裡，桌機的 `USB_MTPDISK_SERIAL` 永遠沒有
定義，所以平常的 `make inocheck` 走不到它。多了一個目標把它也編一次：

```bash
cd tools/sim
make inocheck-mtp      # 假裝 USB Type 是 Serial + MTP Disk
```

`fake_mtp/MTP_Teensy.h` 是照著真的那份抄的替身介面（跟 `fake_usbhost/` 同一個
理由存在）。真的那份如果改了簽章，這裡會編不過 —— 那正是我們想知道的事。

## USB Host 埠（接電腦鍵盤用）

Teensy 4.1 底部靠近 SD 卡槽那排 5 針就是**獨立的 USB Host 埠**，跟燒錄用的
Micro-USB 完全分開，所以插著鍵盤演奏的同時還是可以看序列埠訊息。

> **這個埠原本是給 MIDI 鍵盤用的，現在不是了。** USB MIDI 從頭到尾沒有收到過
> 任何一個封包：裝置列舉正常、描述元裡有 class 1 / subclass 3 的 MIDI Streaming
> 介面、IN 端點也在，`MIDIDevice_BigBuffer` 也確實認領了它 —— 就是沒有資料。
> 換 hub、換鍵盤、打開 `USBHOST_PRINT_DEBUG` 都試過，查不出原因。
>
> 與其留著一條不會動的路徑，改用一般 USB 電腦鍵盤當琴鍵（見下一節），
> 同一個埠、不用多接任何線、而且鍵位邏輯在桌機上完整測得到。
> 舊的程式碼與當時的除錯筆記留在 `舊版備份/midi_in.cpp`。

### 接線

把 USB A 母座的四條線接到那 5 針：

| Teensy 4.1 針腳 | USB A 母座 | 線色 |
|---|---|---|
| 5V  | 1 (VBUS) | 紅 |
| D-  | 2        | 白 |
| D+  | 3        | 綠 |
| GND | 4        | 黑 |
| SHLD| 外殼      | 不接也能動 |

D+/D- 接反的話裝置**完全不會被列舉出來，而且沒有任何錯誤訊息** —— 遇到「插了
沒反應」先檢查這兩條。

電源方面，這個埠的 5V 來自 VUSB，由板上的限流開關控制。如果你改用外部電源
從 VIN 供電，**必須割開背面 VUSB 與 VIN 之間的走線**，否則會把電倒灌回電腦的
USB 埠。一般薄膜鍵盤是匯流排供電的低耗電裝置，用電腦供電時直接接就好。

### 兩個要知道的限制

**音域**：素材通常只涵蓋一個八度（例如 C4~B4）。彈到那個範圍以外時，程式會挑
音高最接近的 profile 再移調，聲音出得來但離得越遠越不像。想彈整台鍵盤就多錄
幾個八度的素材 —— 音色庫可以放 16 組，按 `v` 看目前的覆蓋範圍。

**分析與訓練會阻塞**：按 `a` 或 `t` 的那段期間鍵盤不會有反應。程式在進去之前
會先把壓著的音收乾淨，所以出來不會有卡住的音一直響。

### 複音負載

`TC_PARTIAL_BUDGET`（預設 320）會在聲部變多時自動縮減每個聲部的諧波數，
所以 8 個音不會是 1 個音的 8 倍成本：

| 同時按鍵 | 1 | 2 | 3 | 4 | 5 | 6 | 7 | 8 |
|---|---|---|---|---|---|---|---|---|
| 相對成本 | 1.00x | 2.01x | 2.99x | 3.91x | 4.64x | 5.02x | 5.24x | 5.55x |

### 燒錄前先做編譯檢查

`kbd_in.cpp` 的 USB 區段平常被 `TC_USE_USB_KBD=0` 整段跳過，所以**桌機編得過
不代表 Teensy 編得過**。這件事踩過幾次：區域變數取名 `DEC` 撞上 `Print.h` 的
`#define DEC 10`；漏掉 `#include <Arduino.h>`，真機靠 `USBHost_t36.h` 間接帶
進來所以看不出來。

`tools/sim/fake_usbhost/` 放了一份只有介面、沒有實作的假標頭，可以在桌機把那段
路徑編一次：

```bash
cd tools/sim && make usbcheck
```

### 測試把自己要驗的前提補上了

USB Host 從 `midi_in.cpp` 搬到 `kbd_in.cpp` 時，`#include "config.h"` 沒有跟著
搬。於是 `TC_USE_USB_KBD` 沒有定義，而 **`#if 未定義的巨集` 在 C++ 裡的值是 0**
—— 整段 USB Host 被靜靜編掉，換成兩個空函式。編得過、燒得進去、開機一切正常，
只是插上鍵盤永遠沒反應。

`usbcheck` 沒抓到，因為它自己會 `-DTC_USE_USB_KBD=1` —— **它把自己要驗的那個
前提補上了**，所以在那個目標底下那段程式碼永遠是活的。這是這一類編譯開關測試
共通的陷阱：驗「這段程式碼編得過」不等於驗「這段程式碼會被編進去」。

兩道防線：

1. `kbd_in.cpp` 開頭有 `#if !defined(TC_USE_USB_KBD)` → `#error`。忘了 include
   會變成編譯錯誤，而不是沉默的行為改變。
2. `usbcheck` 多跑一次「不給任何 `-D`、假裝在 `__IMXRT1062__` 上」的預處理，
   展開之後 `usbHost.begin` 必須還在。把 `#include "config.h"` 拿掉再跑一次
   確認它真的會失敗（負對照），才算數。

### `.ino` 也要編一次

```bash
cd tools/sim && make inocheck
```

`.ino` 一直是唯一沒有編譯涵蓋的檔案，因此漏掉過兩次錯。最近一次是把
`gUiOctave` 宣告在 `showIdle()` 後面 —— **Arduino 的預處理只會自動補「函式
原型」，不補變數宣告**，所以在 `.ino` 裡變數的位置是有意義的，但寫 C++ 的直覺
不會想到這件事。`inocheck` 把 `.ino` 複製成 `.cpp`、用 `tools/sim/` 的假標頭
（`Audio.h` 的 `TC_INO_CHECK` 區段、`Wire.h`、`fake_usbhost/`）編一次。

一個誠實的差異：**g++ 比 Arduino 嚴格**。Arduino 會自動補函式原型，g++ 不會，
所以「函式用在定義之前」`inocheck` 會報錯而 Arduino 能過。遇到就在 `.ino` 裡
補一行前置宣告（`uiRenderFwd` 就是這樣處理的），不要去動這個目標。

另外選單頁的項目數改用 `UI_PAGE_DEF` 巨集由 `sizeof` 算出來，不再手寫 ——
「加了項目忘了改數字」不會有任何編譯警告，只能靠盯著 OLED 才發現。

## 用一般 USB 電腦鍵盤當琴鍵（不用接任何線）

USB Host 埠一旦焊好，隨手拿一把 USB 鍵盤插上去就能彈，而且連選單也能操作 ——
這條路完全不需要那 16 顆按鈕，也是取代 MIDI 鍵盤的那條路。

### 鍵位

```
  上排（高八度）    2 3   5 6 7          <- 黑鍵
                   Q W E R T Y U        <- 白鍵   C5 ~ B5

  下排（原位）      S D   G H J          <- 黑鍵
                   Z X C V B N M        <- 白鍵   C4 ~ B4
```

| 鍵 | 作用 |
|---|---|
| 左 / 右方向鍵 | 整體移調 −1 / +1 個八度 |
| 空白鍵 | 全部停音 |
| 上 / 下方向鍵 | 選單游標移動 |
| Enter | 確定 / 進入子選單 |
| Esc 或 Backspace | 返回 |

這是 DAW 常用的打字鍵盤佈局（Ableton、FL Studio 都是這一套），下排從 C4 起，
剛好對上音色庫的原位，也跟 12 顆實體琴鍵的音一致。兩種輸入共用同一個八度設定，
切換時音高不會跳掉。

選單裡 **Play → PC keyboard map** 會把鍵位印到序列埠，OLED 上也有一份縮寫。

### 用的是「實體位置」，不是字母

程式呼叫的是 `attachRawPress()`，拿到的是 HID usage code，對應鍵盤上的**實體
位置**。如果用 `attachPress()` 拿已經套過佈局的字元，換一把 AZERTY 鍵盤或使用者
切到別的輸入法，整組琴鍵就跑掉了。Z 鍵永遠是左下角那一顆，這一點在任何佈局下
都成立。

### 兩個必須先知道的限制

**一、和弦數有上限，而且是鍵盤硬體的限制。**
USB HID 的 boot protocol 一次只回報 6 個按鍵；更麻煩的是沒有防鬼鍵設計的薄膜
鍵盤，某些三鍵組合就會漏鍵或多出沒按的鍵（矩陣掃描的老問題，跟 4×3 按鍵矩陣
會鬼鍵是同一回事）。程式端無解。想彈四音以上的和弦，要挑標示 **N-key rollover**
或 **anti-ghosting** 的機械鍵盤。這台合成器有 8 個聲部，是鍵盤先撐不住。

**二、沒有力度。** HID 鍵盤只回報按下/放開，量不出力道，跟實體按鈕一樣。
不過素材本來也只有單一力度（例如 `Trumpet.vib.ff`），有力度也還原不出
「彈越大聲、泛音越多」那部分。

### 順便是一個診斷工具

電腦鍵盤走的是 **interrupt 端點**，USB MIDI 走的是 **bulk 端點**，路徑不同 ——
所以當初它同時也回答了「USB Host 埠本身到底有沒有焊好」這個問題：

| 電腦鍵盤 | MIDI 鍵盤 | 結論 |
|---|---|---|
| 能用 | 不能用 | 接線與供電**確定沒問題**，問題在 MIDI 裝置本身或它的 USB 協定層 |
| 不能用 | 不能用 | 問題在硬體：D+/D− 接反、5V 沒到、GND 沒接 |

實測結果是第一列 —— 電腦鍵盤一插就通，MIDI 一則都收不到。這是後來決定整個
移除 USB MIDI 的直接依據：硬體沒問題，而軟體那端已經沒有可查的了。

### 桌機測得到

```bash
cd tools/sim && make kbd_test && ./kbd_test
```

`kbd_in.cpp` 完全不碰 USBHost_t36，鍵碼對應、和弦追蹤、移調、佇列都是純邏輯，
測試會塞一個假的合成器進去，直接檢查「Z 鍵送出的音高是不是 60」。這很重要 ——
USB Host 埠本身就有問題，如果連鍵位對應都要燒進去用耳朵聽，根本分不出是程式錯
還是 USB 沒通。

測試涵蓋 12 節，包含幾個實體琴鍵那邊踩過的坑：鍵碼撞號（某顆鍵發出別人的音，
不會當機所以很難察覺）、移調時用新音高去 `noteOff` 導致舊音關不掉、重複的按下
報告讓音卡住。加測試前都先確認過「把修正拿掉，測試真的會失敗」。

## 按鈕接線（16 顆）

> 如果你打算用上面的 USB 電腦鍵盤，這一整段可以跳過 —— 一顆按鈕都不用接。
> 下面這套適合做成獨立成品（不想外接鍵盤）的情況。

### audio shield 到底佔用了哪些腳位

官方表格（Rev D，Teensy 4.x）：

| 功能 | 腳位 |
|---|---|
| 音訊資料 | 7, 8, 20, 21, 23 |
| 音訊控制（I2C） | 18, 19 |
| SD 卡 | 10, 11, 12, 13 |
| 記憶體晶片 | 6 |
| 音量旋鈕 | 15（沒焊旋鈕就是空的） |

所以 shield 上**空著的孔有 12 個**：0 1 2 3 4 5 9 14 15 16 17 22。

（早期這份文件寫成 shield 有用到 9、15、22，那是錯的，已更正。）

### 配置

總共要 16 顆按鈕，shield 只有 12 個空孔放不下，所以分兩處：

**選單 4 顆 → shield 底排 2、3、4、5**

底排連續的四個空孔，而且緊鄰右下角的 GND，四顆可以共用同一個 GND，線最短。
順序是 5=返回、4=確定、3=下、2=上。

**12 琴鍵 → Teensy 尾端，白鍵一排、黑鍵一排**

Teensy 4.1 尾端本來就是兩排分開的：**近側那排（跟 0~12 同一邊）是 24~33，
遠側那排（跟 13~23 同一邊）是 34~41**。所以照真實鍵盤的樣子分：

| | 白鍵（近側那排） | | 黑鍵（遠側那排） |
|---|---|---|---|
| C4 | 24 | C#4 | 34 |
| D4 | 25 | D#4 | 35 |
| E4 | 26 | F#4 | 36 |
| F4 | 27 | G#4 | 37 |
| G4 | 28 | A#4 | 38 |
| A4 | 29 | | |
| B4 | 30 | | |

兩組各自連續，而且「上面一排全是黑鍵、下面一排全是白鍵」，插錯位置一眼看得出來。
剩下沒用到的是 31 32 33（近側）和 39 40 41（遠側）。

## 尾端懸空怎麼接

Teensy 4.1 出廠時尾端那 18 個孔（24~41）**是空的沒有排針**，而 audio shield 只
覆蓋到 0~23。把 Teensy 疊在 shield 上之後，尾端就懸空在麵包板上方。

三種接法，依「可逆程度」排序：

**一、焊排母（母座）朝上 + 杜邦線**

最保險。近側焊一排 10P（24~33）、遠側焊一排 8P（34~41），開口朝上，再用杜邦線
接到麵包板上的按鈕。完全不受高度影響，之後想改配置也不用拆焊。缺點是尾端仍然
懸空，要另外用東西墊著。

**二、焊排針朝下，插進麵包板**

最整齊，而且尾端有了支撐就不再懸空。但**高度必須先量**：Teensy 底面到麵包板
表面的距離取決於 shield 那疊有多高。一般排針插入麵包板的長度約 6 mm，如果量到
的距離明顯超過，就要用「長腳排針」（tail 11 mm 那種）或先在麵包板上插一排排母
墊高。

量的方法：拿一支排針靠在 Teensy 尾端旁邊，看它能不能同時碰到板子的孔和麵包板。

**三、直接把線焊在孔上**

最省事，13 條線直接焊上去（12 顆琴鍵 + 1 條 GND）。不可逆，而且之後要改配置得
重新拆焊，但如果這是最終形態就沒問題。

**不管哪一種都要記得拉 GND。** 可以從 shield 上排右側的 `G` 孔、或 Teensy 上任
一個 GND 拉一條過去當 12 顆琴鍵的共同地線。

**接法都一樣**：按鈕一腳接對應腳位、另一腳接 GND。程式用內部上拉，
不需要任何電阻或二極體。

還空著沒用到的：shield 上的 0 1 9 14 15 16 17 22，以及 Teensy 尾端的 36~41。

### 使用方式

從選單 `Play → Keyboard 12 keys` 進入琴鍵模式，按返回鍵離開。
OLED 會顯示按著哪些音、聲部數、目前八度。`Play → Key octave` 可以整體移調 ±2 個八度。

**為什麼直接接 12 支而不是 4×3 矩陣。** 矩陣只要 7 支，但同時按三顆以上會出現
鬼鍵（沒按的音也會響），要避免就得在每顆按鍵串一顆二極體。Teensy 4.1 的腳位
綽綽有餘，而且這台合成器有 8 個聲部，直接接才真的彈得出和弦。

力度是固定的：輕觸開關量不出力度。要有力度得換成有壓力感測的鍵，而且素材本來
就只有單一力度，量得出來也還原不了。

## 樂譜：半音階與卡農

兩份譜是兩種用途，不會互相取代：

| | 半音階 | 卡農 |
|---|---|---|
| 叫出來 | `p` / `w`、選單 `Scale` | `j` / `j n`、選單 `Canon` |
| 錄成 | `PLAY.WAV` | `CANON.WAV` |
| 織度 | 單音，彼此不重疊 | 三聲部同時發聲 |
| 用途 | **量的**：`evaluate.py` 逐音切開比對 | **聽的**：這個音色拿來演奏音樂像不像 |

預設模式永遠是半音階。`startPlay()` 每次都明確指定要彈哪一份 —— 只要有一條
路徑忘了設，下一次按 `w` 就會把卡農錄進 `PLAY.WAV`，而那是所有評測數字的輸入。
這種錯不會有任何錯誤訊息，所以寧可每次都寫一次。

### 半音階

**每個半音一個單音、彼此不重疊**。這不是拿來聽的，是拿來量的 —— `evaluate.py`
要能自動切開每一個音，才有辦法跟對應的素材算包絡相關性與頻譜距離。

音域是動態的：**音色庫實際涵蓋的範圍，再往上一個八度**。以前寫死 C3~B4，那個
範圍是憑空訂的 —— 只錄了 C4~B4 的話，C3 得往下移調 12 個半音，聽起來當然不像，
卻很容易被誤以為是合成器的問題。

### 卡農

D 大調三聲部，和聲進行 `D A Bm F#m G D G A`，重複三輪，約 45 秒。三輪刻意寫成
三種織度：**A 段二分音符**（先把和聲聽清楚）、**B 段四分音符**、**C 段八分音符
琶音**。同一個音色在長音與快速音群下的差別 —— 起音與釋放的品質 —— 只有在 C 段
才聽得出來，而那正是逐音比對量不到的東西。

這份譜曾經因為「沒辦法逐音比對」被整份移除。接回來的理由是：LSD 與包絡相關性
再漂亮，也回答不了「拿來彈一首曲子像不像」。舊碼在 `舊版備份/score_canon.cpp`，
差別只有一個 —— 音高不再寫死。

#### 音高怎麼跟著音色庫走

原譜是 D 大調、低音到 D3(50)、旋律到 F#5(78)，跨 29 個半音。音色庫只有
C4~B4 時可用窗（涵蓋範圍 + 一個八度）只有 24 個半音 —— 整首一起移一定有一端
出界，照原調彈則低音每個音都要往下移調 10 個半音以上，聽起來不像，而且很容易
被誤會成合成器壞掉（跟半音階以前寫死 C3~B4 是同一個坑）。

作法是**逐聲部各自選一個八度**：

- **只移整個八度。** 移 12 的倍數不會改調性，卡農還是 D 大調；移別的量就是換
  了一首曲子。
- **逐聲部選，不是整首一起移。** 三條線各自都塞得進窗裡，而且每條線內部的音程
  完全不變 —— 不會出現「某幾個音突然跳一個八度」那種破壞旋律的折疊。密集位置
  本來就是常見的簡化編法。
- **成本函數裡「往下出界」的權重是「往上」的兩倍。** 往下移調要憑空生出比素材
  更低的基頻，往上只是既有諧波的重新配置，兩者不對等。
- **低音不能翻到旋律上面。** 音色庫整個在低音域時，內聲部與旋律會被一路往下推，
  而低音本來就在下面不用動 —— 結果低音跑到旋律上面去，聽起來就不是卡農了。
  用平均音高當硬條件擋住（三條線本來就交疊，用最高／最低音判斷會過度敏感）。

實測：音色庫 C4~B4 → 低音 +12、內聲部 ±0、旋律 ±0，全部落在 62~78。
音色庫整個在低音域（C2~B2）→ 旋律 −24、內聲部 −24、低音 −12。

#### 同一瞬間不能有兩個一樣的音高

這是 `Player` 的限制，不是音樂上的講究：note-off 是用**音高**當鍵的（`_pend`
裡存的就是 midi），所以兩個同音高的音疊在一起時，**先結束的那一個會把還在響的
一起關掉**。症狀是某幾個小節低音突然斷半拍，而且只在特定和弦出現 —— 用耳朵
幾乎不可能定位。

寫死音高的舊版不會遇到（低音固定在下面一個八度）。是「跟著音色庫走」把低音
搬進內聲部的音域之後才出現的新情況：8 個和弦裡有 4 個會撞到。

處理方式是**合併**而不是丟掉其中一個：時間取聯集、力度取大的、聲部取音比較長
的那一條。聽感上本來就只會聽到一個音。音色庫 C4~B4 時 112 個音符會合併掉 23 個。
`score_test` 有一條「沒有兩個音同時同音高」的檢查專門守這件事。

### 踩過的坑：樂譜必須依 tick 排序

`Player::fireTick()` 是「一路往前掃」的，只在 `_notes[_cursor].tick == _tick`
時才前進。第一版產生器照聲部書寫（低音整輪、再旋律整輪），順序不對，結果是
**只有 A 段的低音在響、之後 30 秒全靜音**。

更值得記的是：`score_test` 當時**沒抓到**這個 bug，因為它用 `polyAt()` 檢查
「每個 tick 有沒有聲音」，那個檢查不在乎陣列順序。現在補了一項「音符依 tick
遞增排序」的測試，而排序本身統一在 `buildScore()` 做，產生器就能維持照聲部
書寫的可讀性。

## 四顆按鈕 + OLED 選單（不用接電腦就能操作）

### 接線

每顆輕觸開關**一腳接下列腳位、另一腳接 GND**。用內部上拉，不需要外接電阻。

| 按鈕 | 腳位 | 選單中 | 數值編輯中 |
|---|---|---|---|
| 上 UP | 2 | 游標往上（可循環） | 數值 +1（按住連發） |
| 下 DOWN | 3 | 游標往下 | 數值 −1（按住連發） |
| 確定 OK | 4 | 進子選單 / 執行 / 進入數值編輯 | 存檔並離開 |
| 返回 BACK | 5 | 回上一層 | 存檔並離開 |

腳位 2、3 沿用原本的錄音／演奏按鈕，**線不用重接**，只是意義改成上／下。
4 和 5 是新增的。Teensy 4.1 上 4、5、14、16、17、24~33 都沒被 audio shield
佔用，要換腳位改 `config.h` 的 `TC_BTN_*` 即可。

### 選單

```
TimbreClone
├ Play      Keyboard / PC kbd map / Scale / Scale+record / Canon / Canon+record / Stop / Octave / Volume
├ Sampling  Record 1 note / Auto sampling / Input monitor / Mic gain / Mic-Line
├ Timbre    Load all WAV / Load newest SET / Analyze REC / Bank coverage / Reload profile / Clear
├ Training  Epochs / MLP on-off / Reload MODEL
└ Status    讓開選單去看原本的狀態面板（按返回回來）
```

只放實際的操作流程。CSV 匯出、SD 列檔這些除錯用的留在序列埠 ——
它們的輸出本來就是給人在電腦上讀的，搬到 128x64 也看不清楚。

標籤一律英文：U8g2 的小點陣字型沒有中文字符，塞中文會變成一排豆腐。序列埠
不受影響，那邊仍然是完整的中文訊息。

### 三個設計決定

**選單項目不自己做事，只回傳一個指令字串**，交給既有的 `handleCommand()` 執行。
所以錄音／分析／訓練那些流程仍然只有一份實作，序列埠也維持完全可用。否則同一
個功能會有兩套程式碼，改了一邊忘了另一邊是遲早的事。

**`ui.cpp` 不碰 Arduino 的任何東西**（沒有 `digitalRead`、沒有 u8g2），導航純粹
是狀態機，硬體相關的部分全在 `buttons.cpp`。所以 `make ui_test` 在桌機上就能驗
「按下去有沒有跑到對的地方」—— 前面 USB MIDI 那段因為只能在硬體上驗，來回花掉
好幾輪，這次不重蹈覆轍。

**忙碌狀態自動把選單推開**：這件事做在 `displaySetState()` 裡，只要進入非 IDLE
的狀態就關掉選單。不是在每個流程各自呼叫 —— 那種散在各處的呼叫遲早會漏掉一個，
然後某個分析的進度條就永遠看不到。

### 去彈跳

用「狀態穩定 20 ms 才承認」，不是按下就 `delay()`。輕觸開關的彈跳通常 1~5 ms，
接觸不良的更久；用 `delay` 會把 `loop()` 卡住，而這支程式的 loop 還要餵 USB Host
和 SD 寫入。上下鍵按住 400 ms 後每 120 ms 連發一次，調 micGain（0~63）才不用
按 63 下。

## OLED 面板

五種畫面：`READY` / `RECORDING` / `ANALYZING` / `TRAINING` / `PLAYING`，
右上角固定顯示目前音源模式（`MLP` 或 `KEYFR`），底部是 SD 狀態與訓練集統計。

分析與訓練是阻塞式流程，所以兩者都有進度回呼餵給面板——訓練時可以直接在
面板上看 epoch 與誤差往下掉，不用盯著序列埠。

面板用 ASCII 顯示。U8g2 的 CJK 字型動輒 1 MB 以上，而 128×64 只放得下兩三個
中文字，資訊密度反而更差；序列埠仍然是完整中文。

**接錯或買到別顆驅動 IC 時**：開機會印出 I2C 掃描結果，正常應該看到
`0x0A`（SGTL5000）與 `0x3C`（OLED）。畫面左右偏移 2 pixel 表示是 SH1106，
改 `config.h` 裡 `TC_OLED_SSD1306` / `TC_OLED_SH1106` / `TC_OLED_SSD1309`
三個開關即可，不必換函式庫。

## 最重要的一件事：不要走「喇叭 → 空氣 → 麥克風」

想用電腦／手機上的軟體音源（GarageBand 之類）當素材時，**把聲音放出來讓麥克風
收**是最糟的一條路。實測過兩次，兩次都是同一個結論。

第二次的資料（GarageBand 鋼琴 C4~B5，12 個白鍵，跟 Iowa MIS 的乾淨鋼琴逐諧波對照）：

| 頻段 | 錄到的相對於乾淨素材 |
|---|---|
| 250 ~ 500 Hz | **−27 dB** |
| 500 ~ 1000 Hz | −8 ~ −14 dB |
| 1 ~ 1.5 kHz | −4 dB |
| 1.5 ~ 3.2 kHz | **+3 ~ +7 dB** |

一個不需要參考素材的旁證：鋼琴在這個音域，基頻幾乎一定是最強的那根諧波。
這批錄音裡**基頻是最強諧波的只有 G5(785 Hz) 與 B5(988 Hz)** —— 785 Hz 以下
全部是第 2~7 根諧波比基頻強。這就是一個 500~700 Hz 高通的簽名。

後果用音色距離量出來（`tools/sim/envdist`，單位 dB）：

| 比較 | 距離 |
|---|---|
| 乾淨鋼琴 C4 vs 乾淨鋼琴 G4（同一台琴） | 2.13 |
| 乾淨鋼琴 C4 vs **小提琴** C4 | 4.90 |
| **錄到的 C4 vs 乾淨鋼琴 C4** | **3.91** |
| **錄到的 G4 vs 乾淨鋼琴 G4** | **5.69** |
| 錄到的 G4 vs 小提琴 C4 | 2.34 |

最後一行是重點：**錄下來的鋼琴，頻譜上比較像小提琴，而不像鋼琴。**
合成器忠實地重現了它拿到的東西 —— 問題發生在它之前。

### 三條路，由好到壞

1. **匯出 WAV 丟進 SD 卡**，然後 `n *`。完全沒有類比鏈，最準。
2. **3.5mm 線接 audio shield 的 LINE IN**，按 `i` 切到線性輸入。
   繞開喇叭、房間、麥克風三個環節。`g` 在這個模式下調的是 `lineInLevel`
   （0~15，數字越大越靈敏），一樣把峰值調到 0.3~0.8。
3. 真的要用麥克風收喇叭：至少別用筆電／手機內建喇叭，而且增益要調夠
   —— 上面那批的峰值只有 0.075~0.20，白白浪費 14 dB 動態。

### 這件事偵測不出來，我試過

錄完的判定面板本來想加一條「基頻異常弱」的規則，量了 68 個乾淨素材之後放棄：

| | 基頻相對最強諧波的中位數 | 低於 −10 dB 的比例 |
|---|---|---|
| 鋼琴 | 0.0 dB | 8% |
| 小提琴 | 0.0 dB | 0% |
| 長笛 | −5.6 dB | 0% |
| **小號** | **−12.1 dB** | **59%** |
| 這批壞掉的錄音 | −8.9 dB | 42% |

真的小號本來就沒什麼基頻，而且**也是越低音越弱**（A3 −24 dB → A5 −1 dB），
跟喇叭高通的簽名一模一樣。任何抓得到這批壞錄音的門檻，都會把每一個小號低音
一起抓進去。沒有參考素材的話，單一段錄音分不出「樂器本來就這樣」和
「錄音鏈把低頻吃掉了」。

所以這一條沒有做成警告。與其做一個對小號整天亂叫的偵測，不如把這件事寫清楚。

## 錄音錄得好一點的訣竅

分析器需要一個**乾淨、持續、單一音高**的樣本。實務上：

- 讓那個音**拉滿 2 秒**，中間不要換弓換氣造成音量大起大落。
- 靠近麥克風，但不要爆表。峰值落在 0.3~0.8 最理想
  （`micGain` 在 `TimbreClone.ino` 的 `sgtl.micGain(36)`，範圍 0~63）。
- 房間要安靜。背景噪音會被算進「噪聲比」，合成出來會多一層沙沙聲。
- **不要錄和弦**，YIN 抓不到基頻會直接放棄。
- 音高落在 65 Hz ~ 1500 Hz 之間（可在 `config.h` 調 `TC_F0_MIN` / `TC_F0_MAX`）。

### 錄完會直接告訴你行不行

以前只有「多次起音」會停在畫面上，其餘一律直接跳走。結果是削波、太小聲、
觸發被噪音搶先這些問題**完全沒有跡象**，要等到合成出來覺得不像，才回頭一個
一個猜。實際查兩份用手機喇叭放給麥克風收的 `REC.WAV` 就是這樣浪費掉的。

現在 `r` 錄完（以及連續採樣的每一個音）都會出現判定面板：

```
        REC OK
  C4 262Hz  1.80s
  pk0.45 snr48 dec0.55
  levels look good
  added to bank
```

判定不合格時面板會**停著等你按鍵**，而且不會自動演奏 —— 那會蓋掉判定，
而判定正是重點。合格的話顯示 4 秒後才自動演奏。

| 顯示 | 意思 | 怎麼改 |
|---|---|---|
| `N notes in one take` | 一次錄到不只一個音 | 只彈一次，讓它自然響完 |
| `clipped x%` | 削波，波形被削平 | 按 `g` 調低 micGain |
| `too quiet: peak x` | 電平低而且埋在噪音裡 | 調高增益或靠近麥克風 |
| `noisy: SNR x dB` | 觸發被環境噪音搶先 | 換安靜的環境，或調高 `s` 的門檻 |
| `note too short` | 包絡量不出衰減走勢 | 音拉長到 1~2 秒 |
| `no decay measured` | 幾乎不衰減 | 管風琴／長弓弦樂是正常的，撥弦樂器就有問題 |

門檻不是憑感覺訂的，是拿實際錄壞的檔案量出來的（見 `rec_check.cpp` 的檔頭）。
規則本身有桌機測試（`make reccheck_test`），也可以拿真實 WAV 跑一遍看結論：

```bash
cd tools/sim && make recscan
./recscan 你的素材/*.wav
```

兩個真實素材抓出來的誤判，已經寫成回歸測試：

- **峰值低不等於錄壞了。** Iowa MIS 的鋼琴原始素材峰值只有 0.033，但訊噪比
  40 dB —— 那是拿來當基準的乾淨錄音。錄音室母帶的絕對電平本來就可以很低。
  所以「太小聲」改成峰值與訊噪比**同時**不合格才算數。
- **「量不到訊噪比」不等於「訊噪比很好」。** 連續採樣有 93 ms 前置緩衝，音一
  觸發就從緩衝最前面開始寫檔，起音正好落在第 0 格，前面沒有任何一格可以當底噪。
  那時候面板顯示 `snr--`，判定跳過所有跟訊噪比有關的規則。

## 遇到問題

| 症狀 | 可能原因 |
|---|---|
| `[SD] 初始化失敗` | 卡沒插好，或格式不是 FAT32/exFAT |
| `[ANA] 抓不到基頻` | 錄到的是和弦、噪音，或音高超出 65~1500 Hz |
| `[ANA] 訊號幾乎是靜音` | `micGain` 太低，或輸入選錯（按 `i` 切換） |
| 聲音破 | 按 `-` 降低音量；或改 `synth.setMasterGain()`（預設 0.18） |
| 聲音太悶 / 太亮 | 素材的高頻被麥克風吃掉了。可以調 `config.h` 的 `TC_N_HARM`（上限 16） |
| 長音會自己慢慢消失 | 檢查印出來的「持續段衰減」。如果樂器該是長音型卻顯示 < 1.0，代表錄音時音量本來就在掉 |
| 每個音都太短促 | 素材的 release 太長被誤判。看 `ADSR` 那行的 R 值 |
| **Windows 說 WAV 檔損毀 / 不給播** | 見下面「Windows 播不出來」那一節。八成是點到 `._CANON.WAV` 那種 macOS 附屬檔 |
| **`o` 監看幾乎沒有訊號** | 見下面「麥克風收不到聲音」那一節。按 `o` 會先印編解碼器自我檢查，看那幾行就知道問題在軟體端還是類比端 |

### 麥克風收不到聲音

按 `o` 進監看時會先做一次**編解碼器自我檢查**：直接把 SGTL5000 的暫存器讀回來。
`inputSelect()` / `micGain()` 的回傳值只證明「I2C 寫出去了」，但真正想知道的是
晶片現在到底是什麼狀態。讀回來的四個暫存器一次把問題切成兩邊：

```
[CODEC] CHIP_ID 0xA011（PARTID 0xA0 = SGTL5000，正常）
[CODEC] ANA_CTRL 0x0032 -> ADC 輸入 MIC，ADC 未靜音
[CODEC] MIC_CTRL 0x0173 -> 前級 40 dB，偏壓 3.00 V / 2.0k
[CODEC] ADC_CTRL 0x00FF -> ADC 增益 左 22.5 dB / 右 22.5 dB
[CODEC] 麥克風總增益 62.5 dB（上限 62.5 dB，打「g 63」拉到底）
```

| 看到什麼 | 代表 | 怎麼辦 |
|---|---|---|
| `I2C 0x0A 沒有回應` | 編解碼器根本沒被設定到 —— 這種狀況**輸出也會是無聲** | 查 Audio Shield 的 SDA(18)/SCL(19)/3.3V/GND 與焊點 |
| `ADC 輸入 LINE IN` | 來源選錯 | 按 `i` 切回 MIC |
| `ADC **靜音中**` | `MUTE_ADC` 沒被清掉 | 按 `i` 兩次重跑 `applyInput()` |
| `偏壓 **關閉（沒有偏壓）**` | 駐極體麥克風沒有供電，一定收不到聲音 | 按 `i` 兩次；`micGain()` 會把 `CHIP_MIC_CTRL` 寫成 `0x0170 \| 前級`，偏壓就會開 |
| 總增益只有 30~40 dB | 沒拉滿 | `g 63`（上限 62.5 dB） |
| **上面全部正常，監看還是沒訊號** | 設定沒問題，問題在類比端 | 往下看 |

#### 先看直流那一行

監看的第二行把**直流偏移**與**交流 RMS** 分開報：

```
[MON] #......... RMS 0.0263 (-31.6 dB)  峰值保持 0.4221  <- 足以觸發
      直流 +0.0261   交流 RMS 0.0012 (-58.4 dB)   <- 直流蓋過交流，這不是收音問題
```

一塊固定的直流墊子會讓總 RMS 看起來「有訊號」，但它不是聲音，而且會把
環境自適應的觸發門檻（`max(下限, 環境噪音 × 邊界)`）整個抬高 ——
症狀就表現成「麥克風很不靈敏」「採樣不觸發」。判斷方法：**出不出聲數字都不動、
而且 96% 以上的能量在 300 Hz 以下**，那就是直流不是聲音。

這個專案自己踩過一次：`setup()` 裡呼叫的是 `adcHighPassFilterDisable()`，
動機是「不要讓濾波器動到最低頻，那會影響諧波振幅的量測」。動機沒錯，
但選錯函式 —— Disable 對應 `ADC_HPF_BYPASS`，PJRC 的註解寫得很清楚是
**「Bypassed and offset not updated」**，也就是直流完全不扣。

正解是 **Freeze**（`ADC_HPF_FREEZE`）：
「Freeze the ADC high-pass filter offset register.
**The offset continues to be subtracted** from the ADC data stream.」
直流照扣，但濾波器不再持續調整，原本擔心的事不會發生。

現在 `applyInput()` 的最後會 `adcHighPassFilterEnable()` → 等 400 ms 讓偏移量
收斂 → `adcHighPassFilterFreeze()`。偏移量跟增益有關，所以每次改輸入來源或
增益都會重新量一次。（`analyzer.cpp` 沒有做去均值，所以這塊直流原本也會
直接汙染包絡與 FFT 的最低幾格 —— 不只是監看好不好看的問題。）

實機修正前後：直流 0.026 → 0.005，交流底噪露出來只有 0.001（−58 dB）。

#### 孤立尖峰會毀掉觸發門檻

同一台機器還有第二個症狀：安靜時交流 RMS 只有 0.001，但輸入偶爾會冒出
孤立的尖峰到 0.28。`s` 採樣的校正期只有 600 ms，撞上一個就完蛋：

```
[SAMP] 環境噪音 0.2767 -> 實際門檻 0.4150
[SAMP] 等待中… 電平 0.0781 / 門檻 0.2763（幾乎沒訊號，按 o 檢查麥克風）
```

之後怎麼彈都不會觸發，而畫面只說「電平 0.06 / 門檻 0.41」。

原因是環境噪音**取校正期間的最大值**。原註解的推論是「會誤觸發的是尖峰不是
平均值，而且實測乾淨背景的 峰值/中位數 只有 1.46，用最大值不會過度保守」——
在乾淨背景下都對，但最大值這個估計量的**崩潰點是 0**：一個離群值就毀掉它。

改成保留最大的 8 個、取其中最小的那個（600 ms 約 207 個 block，≈96 百分位）。
可以吃掉 7 個尖峰，而乾淨背景下它跟最大值幾乎沒有差別（實測背景 99% 是
0.028、最大 0.030）。跟 analyzer 量 `noiseGain` 時「取 5 個點的中位數」是
同一個理由。

`make trigger_test` 第 8 節用同樣的訊號（每 80 個 block 插一個 0.28 的尖峰）
驗證：環境 0.0303、門檻 0.0455、0.20 的音觸發得到。第 9 節是負對照——
同一段訊號餵給舊的最大值估計法，環境 0.28、門檻 0.42，那個音進不去。

尖峰被剔除不代表它們沒問題。校正結束時會回報看到幾個，因為孤立尖峰通常是
數位耦合或接地問題（SD 卡、OLED 排線），麥克風線離它們遠一點會有幫助。

#### 光靠百分位還不夠：block 電平本身要換

實機再跑一次，環境降到 0.1910、門檻 0.2865 —— 好一點，但還是觸發不了。
第 8 大仍然是 0.19，代表 600 ms 的 207 個 block 裡**至少有 8 個**帶著尖峰
（實際上約 4~8%）。百分位擋得住偶發的離群值，擋不住這種密度。

真正的問題在更上游：**block 電平取的是「這個 block 的最大取樣值」**，
而最大值對單一取樣的脈衝毫無抵抗力。同一段訊號用兩種尺度看：

| | 安靜（帶尖峰） | 真的有音 | 比值 |
|---|---|---|---|
| block 最大值 | 0.28 | 0.55 | 2× |
| block RMS | 0.002 | 0.17 | 85× |

改用 RMS 可以分得非常開，但那會換掉整個尺度 —— `TC_TRIG_LEVEL`、
`trigger_test` 裡那些門檻數字全都是拿真實錄音的「block 峰值」量出來的，
README 上那些量測值也會全部失效。

所以改成**取第 4 大的取樣值**（`tcBlockLevel()`，`TC_BLOCK_TOPK = 4`），
單位完全不變：

- **真實樂音**：128 個取樣裡有幾十個貼近峰值（440 Hz 的 block 有 1.3 個週期，
  `|sin| > 0.9` 的取樣佔 29%），第 4 大 ≈ 最大值。實測 0.20 的樂音量到 0.1998。
- **單根脈衝**：只有 1~3 個取樣是大的，第 4 大落回底噪。實測 0.28 的針
  量到 0.0019，就算同一個 block 塞三根針也還是 0.0020。
- **樂音 + 針**：0.20 的樂音配一根 0.90 的針，量到 0.2000 —— 針不會把電平灌高。

這個函式放在 `trigger.h/.cpp` 而不是 `recorder.cpp`，因為它是「什麼時候該開始
錄」的一部分，而且是純函式，桌機測得到。`make trigger_test` 第 10 節連負對照
（取最大值會量到 0.28）一起驗。

**尖峰還是要處理。** 韌體現在只是不再被它們騙，但它們仍然會被錄進素材裡，
變成音檔裡的喀噠聲，也可能讓分析器把起音點抓在針上。

四個暫存器都正確卻收不到聲音，就只剩類比端。**用手指摸 MIC 焊盤**：
62.5 dB 增益下，手指的 50/60 Hz 交流哼聲會讓監看數字明顯跳動。

- **摸了會跳** → ADC 路徑是通的，問題在麥克風本身：駐極體有極性（金屬外殼那一腳
  是 GND），焊反、虛焊、或麥克風壞掉都會是這個症狀。
- **摸了完全不動** → 訊號根本沒進到 ADC。這時候別再調增益了，回去查接線。

（`o` 監看的三頻段是另一件事 —— 那是用來看錄音鏈有沒有把低頻吃掉的，
跟「有沒有訊號」無關。）

### Windows 播不出來

兩個成因，先看檔案大小就能分辨：

**一、點到 `._` 開頭的那個檔。** macOS 把檔案寫到 FAT32/exFAT（SD 卡、隨身碟）時，
會替每個檔案多產生一個 `._同名` 的附屬檔存 Finder 的 metadata。所以卡上會同時有
`CANON.WAV`（真的音訊，好幾 MB）和 `._CANON.WAV`（**4 KB，裡面一個音訊位元組都沒有**，
內容是 `Mac OS X` 標頭加上一句 `This resource fork intentionally left blank`）。
Windows 檔案總管把兩個都顯示成 `CANON`，`._` 那個還排在前面 —— 點下去當然播不出來。

看大小就知道：4 KB 的是附屬檔，MB 級的才是音訊。要清掉的話，
Windows 上 `del /s /a:h ._*` 或 `del /s ._*`，macOS 上退卡前跑 `dot_clean /Volumes/卡名`。

韌體這邊不受影響：`wav_io.cpp` 的三個掃描點都跳過 `.` 開頭的檔案，
分析器讀到它也只會回一句「不是 RIFF」然後跳過。

**二、錄到一半斷電。** WAV 的長度欄位本來只在 `close()` 補正，所以演奏或錄音還沒
結束就斷電、按 reset、或直接拔卡的話，音訊資料明明已經寫進去好幾 MB，
標頭裡的 data 長度卻還是 0。這種檔案最難查的地方是**有些播放器讀得出來**：

| 播放器 | 對 data 長度 = 0 的反應 |
|---|---|
| Windows 檔案總管 / Media Player | 判定損毀，不給播 |
| ffmpeg / QuickTime / Audacity | 自己掃到檔尾，照樣播 |

於是症狀變成「在 Mac 上聽得到，拿到 Windows 就說壞掉」，很容易被當成播放器的問題。
現在 `WavWriter::flushHeader()` 會在錄製途中把長度補到目前為止，`recorder.cpp`
每 2 秒呼叫一次 —— 斷電最多只損失最後 2 秒，檔案本身一定是合法的 WAV。
成本是每 2 秒一個 seek + 8 個位元組 + 一次 flush，相對於 176 KB/s 可以忽略。

`make wavhdr_test` 用「寫一半就不呼叫 close()」模擬斷電，直接檢查磁碟上的位元組，
而且帶一個負對照（不補正的話確實會留下 data=0 的壞檔），確認這條檢查真的擋得住東西。

## 用麥克風採樣（連續採樣模式）

一個人拿著樂器沒辦法同時按鍵盤，所以有專門的模式：按 **`s`** 之後不用再碰鍵盤，
**偵測到聲音就自動錄音、分析、依音高命名存檔、加進音色庫**，然後回到等待狀態。

```
s                進入採樣模式
（彈 C4）        -> 自動錄 2 秒 -> 存成 C4.WAV -> 入庫 -> 顯示覆蓋率
（彈 C#4）       -> Db4.WAV ...
（一路彈上去）
任意鍵            結束，印出總數與音域覆蓋
t                （選用）用剛採到的素材訓練 MLP
p                聽 C3~B4 半音階
```

> 指令**不分大小寫**，`s` 和 `S` 都可以。

### 每一輪一個資料夾

按 `s` 開始採樣時會自動建立 `SET01/`、`SET02/`…，那一輪的音檔全部收在裡面：

```
SET01/
  C4.WAV  D4.WAV  E4.WAV  …
  BANK.BIN          <- 這組音檔算出來的音色庫
```

以前所有音檔都堆在根目錄，**第二輪的 C4.WAV 會直接蓋掉第一輪的**，而且
`n *` 會把不同樂器、不同輪次的素材全部混在一起訓練，從外面完全看不出來。
分資料夾之後，一輪就是自足的一組。要用哪一組：

```
n SET01/          載入那一組的所有音檔
n SET             載入「最近那一組」（選單的 Load newest SET 送的就是這個）
```

`BANK.BIN` 也在裡面，所以想直接換回某一輪的音色，把它複製回根目錄就好，
不必重跑分析。

#### `Load all WAV` 看不到這些音檔

這是踩過的坑：採樣模式錄了十幾個音，回頭按選單的 `Load all WAV` 卻只跑了
**一個**。因為 `Load all WAV` 送的是 `n *`，而 `n *` 只掃**根目錄** ——
採樣的音檔在 `SETnn/` 裡，根目錄剩下的只有 `REC.WAV`（每錄一個音就被覆寫一次的
暫存檔），所以「一個」就是它。

多數情況下其實**不需要重新載入**：採樣模式每收好一個音就已經 `gBank.add()`
並存了根目錄的 `BANK.BIN`，開機時也會自動載回來。先按 `v` 看音域覆蓋，
該有的音都在的話這件事就結束了。

真的要重載（按過 `z` 清空、或想換回舊的一組），用上面的 `n SET` 或 `n SETnn/`。
選單也加了 `Load newest SET` —— 連續採樣是不接電腦的流程，採完卻只能靠序列埠
打資料夾名字才載得回來，那條路本來是斷的。

「最近那一組」的定義是：**這次開機採過的話就是那一組**，否則退回編號最大的。
不單看編號，是因為 `tcSdMakeNextSet` 會把使用者刪掉的號碼補回去 —— 刪了 `SET02`
再採一輪，新的那組叫 `SET02`，而編號最大的 `SET03` 反而是舊的。

另外 `n *` 現在只要發現卡上有 `SETnn` 就會把它們列出來並提示正確的指令，
不會讓人對著「找到 1 個 WAV」乾瞪眼。

**為什麼用流水號不用時間戳記**：Teensy 4.1 的 RTC 要裝鈕扣電池才會走。
沒電池的話每次開機都從同一個時間開始，時間戳記反而會互相覆蓋 —— 比流水號更糟。
流水號只依賴「卡上已經有哪些資料夾」，永遠正確；而且是逐一試號碼而不是取最大值
加一，所以手動刪掉 `SET02` 之後下一輪會補回 `SET02`，號碼不會有斷層。

### 刪除

| 動作 | 序列埠 | 選單 |
|---|---|---|
| 刪根目錄的產生檔（REC / PLAY / 音名檔） | `y y` | Timbre → Delete WAV files |
| 刪**全部**採樣資料夾 | `y s` | Timbre → Delete SET dirs |
| 只刪某一組 | `y s SET02` | （選單沒有，見下） |

兩個刪除頁都把 **Cancel 放第一項**：進去游標停在第 0 項，手滑連按兩下確定
只會取消，不會刪東西。

選單刻意不做「逐一列出 SET01/SET02 讓你挑」——選單的項目表是編譯期常數，
要動態列出得整個改成執行期組裝，為了刪檔加那麼多狀態不划算。想精挑細選的人
本來就坐在電腦前面，序列埠打 `y s SET02` 就好。

刪除範圍嚴格限制在 `SETnn`（SET + **剛好兩位數字**）。`SETTINGS`、`SAMPLES`、
以及一個叫 `SET04` 但其實是**檔案**不是資料夾的東西，都碰不到 —— 這些都有
負對照測試（`make setdir_test`）。誤刪素材是不可逆的，寧可規則嚴一點。

### 觸發：門檻是自動的

按 `s` 之後會**先聽 600 ms 量環境噪音**（面板顯示 `listening to room...`，
這段期間不會觸發），然後：

```
實際門檻 = max(你設的下限, 環境噪音 × 1.5)
安靜線   = max(你設的下限 × 0.6, 環境噪音 × 1.2)
```

觸發要同時滿足三件事：連續 4 個 block 超過門檻、而且**在那之前連續安靜滿
400 ms**。錄完一段之後武裝狀態會被清掉，所以音的尾巴不會再觸發一次。

面板一直顯示 `amb0.021 thr0.045`（環境／門檻）。門檻是自動的，不顯示的話
「怎麼都不觸發」跟「怎麼一直觸發」都會變成無從查起的抱怨。

### 為什麼要改成自動：舊版會整晚亂錄

舊版是固定門檻 0.035。量了實際錄到的檔案才知道餘裕有多小
（12 個檔各取最安靜的 0.3 秒，共 1236 個 block）：

| | block 峰值 |
|---|---|
| 背景噪音 中位 | 0.0207 |
| 背景噪音 99% | 0.0281 |
| **背景噪音 最大** | **0.0301** |
| 固定門檻 | 0.035 |
| **最弱的那個音** | **0.0529** |

背景最大值離門檻只有 1.16 倍（1.3 dB），最弱的音離背景只有 1.76 倍（4.9 dB）。
房間裡多一台風扇就會整晚亂錄——而這正是實際發生的事。

而且舊版還有一個**寫反的保護**：

```cpp
if (pk < _thresh * 0.5f) _quietSince = millis();
...
if (++_hotBlocks >= N && (millis() - _quietSince) > TC_REARM_SILENT_MS)
```

本意是「錄完之後要先安靜一段時間才重新武裝」，寫出來的意思卻是「最後一次
看到安靜是在 400 ms 以前」。背景只要持續高於半個門檻，`_quietSince` 就永遠
不更新，那個差值只會越來越大——**房間越吵，這個保護越不會擋**，正好相反。

現在改成閂鎖：必須「連續」安靜滿 400 ms 才武裝，觸發時消耗掉。持續的噪音
永遠湊不滿那段連續安靜。

### 收到髒東西就丟掉

判定是 `REC_BAD` 的那一筆會**整筆丟棄**：不存檔、不入庫、也不進訓練集
（`TrainSet::truncate()` 把分析時已經堆進去的樣本退回來）。面板顯示 `DROPPED`。

亂觸發真正的損失不是浪費時間，是那些噪音被當成音色寫進 `BANK.BIN`，
之後每個音都受影響，而且從外面看不出來是哪一筆有問題。

### 訊噪餘裕：一個該看的數字

面板上的 `hr12dB` 是這次觸發的訊號比環境噪音高多少。低於
`TC_TRIG_MIN_HEADROOM_DB`（12 dB）會顯示 `low margin - play up`。

以那批實際素材算出來只有 **4.9 dB**——這就是為什麼那次採樣結果不能用。
與其錄完一整輪才發現，不如第一個音就講。

### 這一段的測試

觸發判斷抽成 `trigger.cpp` 的純狀態機（不碰 SD、OLED、Arduino），
桌機餵合成訊號跑完每一條路徑：

```bash
cd tools/sim && make trigger_test
```

含一個**負對照**：把舊版邏輯原封不動抄進測試裡，餵同一段噪音，確認它真的會
觸發 1315 次。沒有這個負對照，「新版 0 次」可能只是因為測試根本沒踩到那條路。

測試也抓到我自己寫的兩個 bug：第一版把「安靜」定義成「低於門檻的 0.6 倍」，
而門檻本身就是環境噪音 × 1.5，於是 0.6 × 門檻 = 0.9 × 環境噪音——環境噪音
自己就會一直跨過這條線，永遠湊不滿連續安靜，**永遠不會武裝，一個音都收不到**。
修掉亂觸發卻換成完全不觸發，一樣沒用。第二個是校正結束時判「環境 < 門檻」，
但那個比較恆真，等於沒判。

### 三個設計重點

**前置緩衝 93 ms。** 等到電平超過門檻時起音已經發生了，直接開始錄會把最關鍵的
起音瞬態切掉——而起音正是人耳辨識樂器最主要的線索。所以永遠保留觸發前
32 個 block（8 KB 環形緩衝）。

**自動命名。** 分析完才知道音高，所以先錄到 `REC.WAV`，分析出 f0 之後複製成
`A4.WAV` 這種名字。音準偏離半音中心超過 35 cent 會警告——音色庫是用音高配對的，
樂器沒調準會配錯。

**覆蓋率提示。** 每採完一個音就列出音域裡哪些半音有了、哪些還缺（缺的用括號標出）。
按 `v` 也可以隨時查。

### 增益怎麼調

```
g          顯示目前 micGain
g 42       設成 42 dB（0~63）
```

採樣模式的 OLED 會顯示即時電平條，錄完序列埠會印峰值：

| 峰值 | 判讀 |
|---|---|
| < 0.05 | 太小聲，調高 `g` 或靠近麥克風 |
| **0.3 ~ 0.8** | **理想** |
| > 0.98 | 削波，調低 `g` |

環境太吵導致誤觸發的話，調高 `config.h` 的 `TC_TRIG_LEVEL`（預設 0.035）。

### 採樣時的實務建議

- **一個半音一個半音來**，音與音之間停半秒以上（`TC_REARM_SILENT_MS`）。
- **音色庫上限 16 組**。整個音域平均分配比擠在一起好——例如要用 C3~B4 兩個八度，
  採 C3、E3、G#3、C4、E4、G#4… 這樣每隔大三度一個，比連續採 12 個半音有用。
- **持續型樂器（弓弦/管樂）要拉穩定的長音**，不要漸強。錄音裡的音量起伏會被
  當成樂器特徵；雖然程式會自動把持續型的漸強壓平，但穩定的素材品質還是更好。
- **每個音只需要 2 秒**（見上面的採樣長度實測）。

## 換其他樂器？

整套流程沒有任何一處是為鋼琴寫死的——分析器量的是「基頻、諧波分佈、包絡、
起音延遲、噪聲比、顫音、非諧性」，這些每種樂器都有。實測小提琴素材：

| 指標 | 鋼琴（12 音） | 小提琴（1 音） |
|---|---|---|
| 諧波 LSD 中段 | 1.5 dB | **1.6 dB** |
| 質心相關性 | 0.895 | **0.914** |
| 自動判定 | 衰減型（本體 6%） | 持續型（本體 70%） |
| 顫音 | 0.1 cents（不加） | 2.3 cents（自動加上） |

分類、顫音、噪聲比全部是量出來的，換樂器不用改任何參數。

### 適用性

| 類別 | 例子 | 結果 |
|---|---|---|
| **好** | 弓弦（小提琴/中提琴/大提琴）、撥弦（吉他/豎琴/古箏）、木管（長笛/單簧管/薩克斯）、銅管、管風琴 | 單音、諧波結構穩定，正是這套方法的設計目標 |
| **普通** | 破音吉他、力度變化極大的銅管 | 音色隨力度劇烈改變，單一力度的素材抓不到 |
| **不行** | 鼓、鈸、鑼 | 沒有穩定基頻，YIN 直接放棄 |
| **不行** | 鐘、鐵琴、管鐘 | 分音不是基頻的整數倍，弦張力那條非諧性公式描述不了 |
| **不行** | 人聲 | 母音會移動共振峰、子音是純噪聲，兩者都超出模型 |

### 換樂器時要注意的三件事

**1. 低音域有硬限制。** YIN 的搜尋視窗是 `TC_FFT_SIZE/2 = 1024` 取樣，
所以能抓到的最低基頻是 44100/1024 ≈ **43 Hz**。大提琴 C2(65Hz) 沒問題，
但貝斯 E1(41Hz) 會失敗——要支援就得把 `TC_FFT_SIZE` 改成 4096，
同時 `TC_F0_MIN` 調低。

**2. 持續型樂器要錄「穩定的長音」，不要漸強。** 我拿到的小提琴素材是
crescendo 然後收弓，包絡相關性只有 0.52——不是合成錯了，而是那條包絡記錄的是
**演奏者的表情**，不是樂器的固有性質。照著重播每個音都會漸強，反而不對。
弓速穩定的長音效果會好很多。

**3. 撥弦樂器要多錄幾個音。** 吉他同一個音在不同弦、不同把位上音色差很多，
音色庫（最多 16 組）建議涵蓋整個要用的音域。

## 已知限制

- 改版後 `PROFILE.BIN` / `MODEL.BIN` 的格式都變了，舊檔會因大小不符被自動忽略，重新分析與訓練即可。
- 這是**加法合成**，重建的是諧波結構。打擊樂、破音吉他、人聲子音這類
  非諧波為主的聲音不會像。適合弦樂、管樂、鋼琴、吉他、電子音色。
- 一次只複製一個音色。要換樂器就重錄。
- 移調範圍太大時（超過兩個八度）共振峰校正會開始失真，這是單樣本的
  物理極限 —— 多錄幾個音高訓練 MLP 會改善。
- USB 電腦鍵盤同時能按幾個音由鍵盤硬體決定：boot protocol 上限 6 個，沒有防鬼鍵
  設計的薄膜鍵盤可能 3 個就開始漏。合成器有 8 個聲部，是鍵盤先撐不住。
- 實體按鈕與電腦鍵盤都量不出力度，力度固定 0.85。素材本來也只有單一力度
  （例如 `Trumpet.vib.ff`），所以「彈越大聲、泛音越多」還原不出來 ——
  要做到得對同一個音錄 pp / mf / ff 三種力度各建一份 profile。
- **USB MIDI 已經移除，不是修好了。** 裝置有列舉、product 字串讀得到、
  MIDI Streaming 描述元正確、bulk IN 0x81 @ 64 bytes，但一則訊息都沒有；
  同一把鍵盤在電腦上正常。查不出原因，改用 USB 電腦鍵盤達成同樣的目的。
  舊程式碼在 `舊版備份/midi_in.cpp`，要重啟這條路隨時找得到。
